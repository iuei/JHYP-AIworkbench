# 责任田：错误页

## 功能描述

负责 401、403、404、500、503 等错误状态页面展示。

## 功能清单

- 401：未授权提示。
- 403：禁止访问提示。
- 404：页面不存在提示。
- 500：服务器错误提示。
- 503：维护或服务不可用提示。

## 入口与出口

- 入口：`src/routes/(errors)/401.tsx`、`403.tsx`、`404.tsx`、`500.tsx`、`503.tsx`，以及根路由或异常流程触发。
- 出口：错误页内已有返回、跳转或辅助操作以当前组件实现为准。

## API 明细

- 暂无真实 API，错误页为前端展示组件。

## 依赖关系

- 依赖：`src/features/errors/`、基础按钮、全局样式。
- 被依赖：路由异常处理、权限/认证异常、服务异常兜底展示。
- 共享字段：错误状态码、提示文案、跳转路径。

## 影响范围

修改错误页会影响异常兜底体验、认证/权限失败展示和不存在页面的用户路径。后续接入真实权限守卫后，401/403 会与认证模块强相关。

## 修改边界

- 可以改：错误页面文案、布局、插图、按钮行为。
- 绝对不能动：未确认不得改变错误路由路径、认证跳转策略、全局路由异常处理。

## 注意事项

- 401 与 403 不要混用：401 偏未登录或认证失效，403 偏已登录但无权限。
- 404 不应吞掉真实运行时错误。
- 错误页要保持轻量，避免依赖复杂业务状态。

## 约束

- 必须复用：现有错误页组件、shadcn/ui Button、全局主题样式。
- 验证要求：代码修改后运行 `pnpm run lint`、`pnpm run build`，路由行为修改需手动访问各错误路由。
