# 责任田：公告

## 功能描述

面向全公司的公告广播：管理员创建 / 编辑 / 发布 / 下线 / 删除公告，员工**每次登录进入系统时**看到弹窗；每条公告可设置「只弹一次（确认后不再弹）」或「每次登录都弹」。

## 功能清单

- **管理页**（`/settings/announcements`，仅管理员）：列表（标题 / 弹出方式 / 状态 / 生效期 / 已读人数 / 更新时间）、关键词搜索、状态筛选、分页（服务端），行内「编辑」「发布 / 下线」「删除」。
- **编辑弹窗**：标题、正文（Markdown，编辑 / 预览切换）、弹出方式（单选）、优先级、生效时间、失效时间；校验在前端（即时反馈）与服务端（权威判定）各一遍。
- **登录弹窗**（`AnnouncementGate`，挂在全站布局）：登录成功后拉一次待弹公告，**排队逐条**展示；**任何关闭方式都上报已读**（点「我知道了」/ ✕ / Esc / 点遮罩），服务端因此不会再弹给这个人。
- **状态流转**：草稿 ⇄ 已发布 → 已归档（草稿与归档只对管理员可见，都不弹）。
- **生效期**：`生效时间` 未到 / `失效时间` 已过都不进待弹列表；列表对"已发布但未生效 / 已过期"额外提示一行，否则管理员看到"已发布"却没人反馈时无法定位原因。
- **审计**：创建、修改、上下线、删除四个动作全部写 `ai_audit_logs`（`announcement_create` / `announcement_update` / `announcement_publish` / `announcement_delete`，`target_type='announcement'`）。

## 入口与出口

- 入口：侧边栏「设置 → 公告管理」（`adminOnly: true`，普通账号看不到该条目）。
- 员工侧**没有独立页面**：公告只在登录时以弹窗出现，关闭后即结束（本轮明确不做「公告中心 / 历史公告」，见「注意事项」）。

## API 明细

员工侧（任何已登录账号，只操作"自己的"数据）：

- `GET /api/announcements/pending`：当前用户这次进入系统应弹的公告（服务端已按有效期 + 弹出方式 + 已读过滤，顺序为优先级倒序 → 发布时间倒序）。
- `POST /api/announcements/:id/ack`：确认已读，204；公告不存在 / 未发布 → 404；重复调用幂等。

管理员侧（`requireUser` + `requireAdmin`）：

- `GET /api/announcements?status=&keyword=&page=&pageSize=`：列表 + `total` + 已读人数；非法状态 400。
- `POST /api/announcements`：新建（默认 `draft`），201。
- `PATCH /api/announcements/:id`：编辑。
- `POST /api/announcements/:id/status`：`{ status: 'draft' | 'published' | 'archived' }`。
- `DELETE /api/announcements/:id`：软删（`deleted_at`），重复删除 404。

## 依赖关系

- 依赖：`AuthenticatedLayout`（弹窗挂载点）、`auth-store` 的 `loginAt`、`MarkdownContent`（`src/components/markdown-content.tsx`）、`DataTable` / `ConfirmDialog` / `ContentSection`（设置中心外壳）、`recordAudit`。
- 被依赖：无模块依赖公告的输出；`global-layout` 只在布局里挂一个 `<AnnouncementGate />`。
- 共享字段：`auth.loginAt`（内存态，登录成功时由 `setAccessToken` 写入，登出 / 刷新清零）。

## 数据模型

- `announcements`（迁移 300）：`title` / `body` / `status`(draft·published·archived) / `display_mode`(once·every_login) / `priority` / `publish_at` / `expire_at` / `created_by` / `published_by` / `published_at` / `deleted_at` / `created_at` / `updated_at`。
- `announcement_reads`（迁移 301）：`(announcement_id, user_id)` 主键 + `read_at`。**主键即幂等保证**，两侧 `ON DELETE CASCADE`。
- 号段：**300 起**（1 快捷导航 / 2–3 用户 / 100+ AI 助手 / 200 竞品分析已占用，复用会被 `schema_migrations` 静默跳过）。

## 影响范围

- **2026-10-10 修复**：员工确认已读只允许生效期内的已发布公告；独立 `db:setup` 初始化会创建公告表，不修改既有表结构。
- 改动弹窗触发时机（`auth-store.loginAt` / `usePendingAnnouncements`）会影响**全站每个页面**：弹窗挂在 `AuthenticatedLayout`，判断写错就会出现"每次切页面都弹"或"永远不弹"。
- 改动 `announcements.mjs` 的 `isPendingForUser` 会同时改变服务端过滤、前端队列与验收脚本三处口径（该方法是指定判定入口，不要在别处再写一遍）。
- 迁移只**新增**表，不改动任何既有表；`server/index.mjs` 的挂载顺序要求公告迁移跑在 AI 助手迁移之后（审计表 `ai_audit_logs` 由后者创建）。
- 新增侧边栏条目会改变普通账号看到的菜单（此前「设置」类目对普通账号也有「显示 / 通知」两项，不受影响）。

## 修改边界

- 可以改：公告的字段、校验规则、队列展示方式、管理页布局、审计动作。
- 绝对不能动：
  - **已读按账号落库**（不能用 localStorage 替代）：换电脑、清缓存会重复弹，且管理员无法统计触达；
  - **任何关闭方式都上报已读**（「我知道了」/ ✕ / Esc / 遮罩一视同仁）：早期只把「我知道了」当确认，用户用 ✕ 关掉后下次登录又弹，表现为"关掉了还一直弹"（2026-09-16 实测缺陷，勿回退）；
  - `usePendingAnnouncements` 的 `staleTime: Infinity` + 关闭窗口聚焦重取：否则窗口切回来会重算待弹列表，已经关掉的公告会凭空再弹一次。

## 注意事项

- **"每次登录"必须真的指登录**：`auth.loginAt` 只存在于内存（不写 cookie），刷新页面即归零，因此"刷新不弹、重新登录才弹"不需要额外状态。判断这条时不要去看 token 是否存在 —— cookie 里的 token 在刷新后依然有效，分不出登录与刷新。
- **关闭即确认的取舍（2026-09-16 定稿）**：任何关闭方式都上报已读，因此 `once` 公告被关掉后**没有二次入口**（本轮没有公告中心）。需要"必须反复看到"的内容请用「每次登录都弹」，不要指望用户点某个按钮。若将来加了公告中心，"关闭即已读"可以放宽为"关闭记已读 + 列表里可回看"。
- **"本次登录已关闭"只存在组件内存里**（`dismissState`）：组件重挂载（HMR / 路由树重建）理论上会让队列从缓存的待弹列表重建，已关掉但未上报成功的公告会再弹一次。实测（touch 布局文件、改路由文件触发 HMR 与路由重建）**未能复现**，React Fast Refresh 保留了组件状态；但如果哪天真的出现，第一个该改的地方是把这个状态提升到模块级 store，而不是再加一层过滤。
- ack 失败会**重试一次**（`useAcknowledgeAnnouncement` 的 `retry: 1`）：写已读是幂等的，而丢一次已读的代价是用户下次登录被同一条公告再打扰一次。
- `POST /:id/status` 的 SQL 里 `$2::text` 的显式转型**不能删**：同一参数既比较 varchar 列又参与 `CASE WHEN`，PostgreSQL 会报 `inconsistent types deduced for parameter $2`（实测 500，见「踩过的坑」）。
- 路由注册顺序：`GET /pending` 必须在 `/:id` 系列之前，否则 `id = 'pending'` 会先命中并返回 400。
- 已读记录**不随下线清空**：`once` 公告下线再上线，已确认过的人不会再被弹（同一条公告不重复打扰）。
- `published_at` 只在**首次**发布时写入（`COALESCE`），"下线 → 改文案 → 再上线"不刷新发布时间。
- **本轮不做**：公告中心 / 历史公告列表、顶栏小铃铛未读红点、按部门/角色定向投放、富文本编辑器、附件。要做"历史回看"时注意：`once` 公告关闭后再也找不到入口，届时需要一个真正的列表页。
- 员工侧接口只按 `req.user.id` 读写，**不提供**任何查他人已读的接口（管理列表只给人数）。

## 约束

- 必须复用：`MarkdownContent`（与 AI 回答共用同一套 Markdown 排版）、`DataTable`、`ConfirmDialog`、`ContentSection`、`recordAudit`、`Button` / `Input` / `Textarea` / `RadioGroup` / `Tabs`。
- 验证要求：`npm run test:server`、`npx vitest run --config vitest.chrome.config.ts --browser.headless`、`pnpm run lint`、`pnpm run build`；改动触发链路时跑 `node server/announcement-verify.mjs`（52 项接口验收）与 `node server/announcement-ui-verify.mjs`（**26 项**浏览器验收，需独立 API + Vite 实例；该脚本里 `[6]` 段专盯"关闭方式即确认"，改动关闭语义时它会红）。
