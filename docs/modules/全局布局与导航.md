# 责任田：全局布局与导航

## 功能描述

负责后台应用的认证布局壳、侧边栏、**顶部栏（含页面标题与模块内二级导航）**、用户入口、全局搜索入口和布局配置入口。

## 功能清单

- 认证布局：为 `_authenticated` 路由组提供统一页面框架，并在 `AuthenticatedLayout` 里**只渲染一次** `Header`。
- 侧边栏导航：展示主导航、分组导航、系统标识和用户信息入口。
- **按角色过滤导航**：`src/components/layout/nav-filter.ts` 的 `filterNavGroupsByRole()` 依据当前账号角色隐藏 `adminOnly` 的**分组与菜单项**（并移除空分组）。管理员看到「设置 → 用户管理」与「AI 治理」分组，普通账号看不到。此前侧边栏数据是静态的，普通账号能看到「用户管理」却因服务端 403 只能看到报错，属于把治理入口暴露给全员。
- 侧边栏支持可展开分组（`NavCollapsible`）：「AI 助手」分组下含「对话」「我的沉淀」两个使用面入口。
- **导航层级保持两级**：AI 治理整体收缩为 `/admin/ai`，**不挂三级菜单**；其五个子页由顶栏中段导航承载（`admin-ai-nav.tsx`）。侧边栏层级不随业务扩张而变深。
- `NavItem.matchPrefix`：入口页在子页路径下保持高亮（如 `/admin/ai` 在 `/admin/ai/knowledge` 下仍激活）。用显式字段而非对所有项做前缀匹配，避免 `/ai-agent` 连带点亮 `/ai-agent/notes`。
- **顶部栏是唯一的页面标题位**：页面名取自当前路由的 `staticData.title`，由 `usePageTitle()` 从最深匹配往上找（子页未声明时继承模块级标题）。页面组件**不再**自己写标题横幅 —— 此前每个页面各写一份 `<Header>`，结果仪表盘漏写页面名、竞品分析的页面名在顶栏与内容区各写一遍，内容区那份还是 `text-2xl` 大字，占掉首屏约 116px。
- 顶部栏承载搜索、主题切换、用户信息入口，并有**常驻背景与底边框**（此前透明无边框，页面顶部看起来"悬空"，滚动后内容会从顶栏底下透出）。
- 顶部栏**全站 sticky**（`Header` 统一传 `fixed`），整页滚动与内容区内部滚动两种模式下都能常驻。
- **Header 中段槽位**：`HeaderSlot`（Portal）让模块把二级导航注入顶栏（AI 助手的「对话 / 我的沉淀」、AI 治理的五个治理页），既省掉内容区一整行、又填掉顶栏中段原本近 1000px 的空白，还纠正了"导航压在页面标题之上"的层级倒置。

## 入口与出口

- 入口：`src/routes/_authenticated/route.tsx` 装配认证布局。
- 页面标题：各路由的 `staticData.title`；模块级路由（`/ai-agent`、`/admin/ai`）声明模块名，子页由导航高亮表达位置。
- Header 槽位：模块 layout 通过 `HeaderSlot` 注入 `agent-nav.tsx` / `admin-ai-nav.tsx`。
- 导航可见性：普通账号只看到非 `adminOnly` 的菜单项；具体路由另有各自的 `beforeLoad` 守卫、服务端接口另有 `adminGuard`，**侧边栏过滤只解决"看得见"**。
- 出口：子路由通过 `Outlet` 渲染到布局内容区。

## API 明细

- 暂无真实 API，当前为前端布局与本地状态。

## 依赖关系

- 依赖：`src/components/ui/`、`src/context/`、`src/stores/auth-store.ts`（读取 `role` 做导航过滤）、`src/lib/cookies.ts`。
- 被依赖：所有 `_authenticated` 下的后台页面。
- 导航数据：`src/components/layout/data/sidebar-data.ts` 是侧边栏入口数据源。
- 角色字段：`src/components/layout/types.ts` 的 `NavItem.adminOnly` / `NavGroup.adminOnly` 声明"仅管理员可见"；过滤逻辑集中在 `nav-filter.ts`（纯函数，便于复用与测试）。
- 页面标题：`src/tanstack-router.d.ts` 为 `StaticDataRouteOption` 增加可选 `title`；`use-page-title.ts` 的 `pickPageTitle()` 是纯函数（可单测），从匹配链由深往浅取第一个标题。
- 顶栏槽位：`header-slot-context.ts` 放 context 与 `useHeaderSlotRef`，`header-slot.tsx` 只放 `HeaderSlotProvider` / `HeaderSlot`（分开是为了满足 Fast Refresh 的"组件文件只导出组件"）。
- 内容宽度：`Main` 统一 `mx-auto w-full max-w-[1280px]`，页面不再各自写 `max-w` 覆盖。

## 影响范围

修改布局会影响所有登录后页面，包括仪表盘、设置中心和后续业务模块。修改侧边栏数据会影响导航入口、全局命令搜索可见性和用户访问路径。

**新增页面必须同步做两件事**：在路由上声明 `staticData: { title: '页面名' }`，否则顶栏不显示页面名（不报错，只是静默降级为只显示控件）；如果该页面属于带二级导航的模块，标题应声明在模块级路由上并由导航表达子页位置。

`Header` 的 `h-16` 必须配合 `shrink-0`：`SidebarInset` 是 flex 纵向容器，`h-16` 只提供 flex-basis，内容区一高（AI 治理等长页面）就会把顶栏挤扁到 37px（实测过），而 Header 被压扁时页面首内容位置会被误判为"更紧凑"。

## 修改边界

- 可以改：布局组件内部展示、导航数据、菜单分组、顶部栏组合、响应式细节。
- 绝对不能动：无需求不得改变 `_authenticated` 路由结构、主题/字体/方向 Provider 的装配顺序、基础 shadcn/ui 组件实现。
- 不得让页面重新自己渲染 `Header`（会导致标题写两遍）；页面级操作走 `HeaderSlot`。

## 注意事项

- 当前 `_authenticated` 已接入本地会话守卫，但不代表真实服务端权限控制。
- 侧边栏和部分 UI 组件包含 RTL/项目定制，更新 shadcn 组件时需要人工合并。
- 内部工作台不展示付费升级、账单、新建团队、添加团队等 SaaS 模板入口。
- 侧边栏系统标识（`sidebar-data.ts` 的 `teams[0]`）名称固定为「JHYP 智能工作台」，副标题为「公司内部工作台」。
- 新增导航入口时，需要同步检查路由文件（含 `staticData.title`）和责任田文档。
- 顶栏槽位在窄屏可横向滚动（`no-scrollbar overflow-x-auto`），不换行 —— 槽位是固定高度容器，换行会撑破顶栏。
- 侧边栏底部与顶部头像仍显示 `sidebar-data.ts` 的静态用户名（未接真实账号），与顶栏页面名无关。

## 约束

- 必须复用：`AuthenticatedLayout`、`Header`、`Main`、`AppSidebar`、`Search`、`ThemeSwitch`、`ProfileDropdown`、`HeaderSlot`。
- 验证要求：布局代码修改后运行 `pnpm run lint`、`pnpm run build`，并在桌面（1680/1280/1024）与移动端（390）检查顶栏高度、横向滚动、AI 助手高度链与侧边栏折叠。
