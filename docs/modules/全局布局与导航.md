# 责任田：全局布局与导航

## 功能描述

负责后台应用的认证布局壳、侧边栏、**顶部栏（含页面标题与模块内二级导航）**、用户入口、全局搜索入口和布局配置入口。

## 功能清单

- 认证布局：为 `_authenticated` 路由组提供统一页面框架，并在 `AuthenticatedLayout` 里**只渲染一次** `Header`。
- 侧边栏导航：展示**按业务域分组的一级入口**、系统标识和用户信息入口。（2026-09-18 之前是"扁平列表、无分组标题"，改成业务域分组后见下方清单与渲染规则。）
- **顶部栏是面包屑、不是单个页面名（2026-09-17）**：`AppBreadcrumb` 渲染 `仪表盘 / AI 治理 / 数据源与导入`（根 / 一级入口 / 当前页，二到三级），取代原先那个只显示页面名的 `h1`。三条硬口径：① **层级名与侧边栏同源** —— 由 `nav-match.ts` 的 `findNavTrail()` 从 `sidebar-data.ts` 反查，不另写一份字面映射（否则加一个类目要改两处）；② **末级仍是全页唯一的 `h1[aria-current=page]`**，这是 2026-09-11 那条"顶部栏是唯一的页面标题位"的**加强而非推翻**（面包屑末级就是页面名）；③ **回退命中时只取业务域那一级当祖先**（`NavTrail.exact`，2026-09-18 把判据从"候选就是路径本身"收紧为"子项真的命中了这个候选"）—— 导航里没有的实体页（`/competitor-analysis/<ASIN>`）若把回退层的子页名也拼上，会得到带冗余中间层的四级面包屑。折叠类目（「产品开发」这类没有落地页的）只作为层级标签渲染成 `span`，**不给点不动的假链接**；根节点的名字取自 `navItems` 里 `url: '/'` 那一项，所以它跟着侧边栏叫「仪表盘」，不会冒出第二个"主页"。
- **页签栏：多页签工作台（2026-09-17）**：`PageTabs` 挂在 `AuthenticatedLayout` 里 `Header` 之下、内容之上，**整条通栏**（不跟 `Main` 的 `max-w-[1280px]` 居中 —— 它是"工作区"级信息，不属于任何单个页面）。语义用 `nav[aria-label='已打开的页面']` 而不是 `role=tablist`：切标签就是**导航到另一个路由**，并没有一个跟着切换的"面板"。三条口径落在 `src/stores/tabs-store.ts`：key = pathname（不含 search，同一页换筛选条件不新开标签）、`sessionStorage` 刷新保持、**换账号即整份清空**（否则 `/admin/users` 这类治理标签会留给下一个登录的人点出 403）。**激活态以 URL 为准**、不看 store 的 `activeKey`：直接敲一个尚未打开过的路径时同步 effect 还没跑，用 `activeKey` 会高亮错标签。
- **`nav-match.ts`：路径命中判定只有一份（2026-09-17）**：`isNavUrlActive()` 从 `nav-group.tsx` 的 `checkIsActive` 里抽出来，侧边栏高亮与面包屑层级判定共用它。两份实现各写一遍必然出现"侧边栏点亮 A、面包屑却说是 B"，而且两边都要各自补测试。`findNavTrail()` 还会**逐级回退**（`/competitor-analysis/<ASIN>`、`/asin-watchlists/items` 在导航里都没有同名项），否则面包屑会退化成一个孤零零的页面名。
- **按角色过滤导航**：`src/components/layout/nav-filter.ts` 的 `filterNavItemsByRole()` 依据当前账号角色隐藏 `adminOnly` 的**一级类目与子项**（子项被清空的折叠类目会整体移除）。管理员看到「AI 治理 / 用户管理 / 公告管理」，普通账号三个都看不到（整组被过滤后不会留下一个空的「系统管理」分组标题）。此前侧边栏数据是静态的，普通账号能看到「用户管理」却因服务端 403 只能看到报错，属于把治理入口暴露给全员。
- 侧边栏一级类目分两种形态：直达页面的 `NavLink`，与**带二级类目的 `NavCollapsible`**（2026-09-18 后只剩「竞品分析」与「产品开发」两个折叠类目）。
  **「AI 助手」2026-09-18 由折叠类目改为叶子类目**：它的「我的沉淀」迁进新增的「知识库」一级类目（`/knowledge`，「个人知识库 ｜ 团队知识库」两个子页由**页面自己的顶栏导航** `KnowledgeNav` 承载，形态与提示词广场完全一致），只剩「对话」一个落点 —— 一个子项的折叠类目在侧边栏只多一层没意义的展开。同源的 `agent-nav.tsx` 因此派生不出任何子项，改为 `items.length > 0` 才渲染 `<nav>`，只保留「可用工具」状态徽标（派生逻辑保留：将来再加子项时导航自动出现）。
- **二级子页只有一份数据源（2026-09-16）**：一级类目与其二级子页都写在 `sidebar-data.ts` 的 `navItems`（+ `adminAiNavItems` 放「AI 治理」的五个治理子页），**顶栏中段导航一律从这里派生**（`nav-children.ts` 的 `findNavChildren()`，角色过滤复用 `nav-filter.ts`），不再各自写一份字面数组。此前 `agent-nav.tsx` 自己写了一份和侧边栏一模一样的「对话 / 我的 ASIN / 我的沉淀」，`admin-ai-nav.tsx` 的五项也在组件内 —— 加一个子页只改一边就会两边不一致。**口径**：顶栏显示什么，由该子页在侧边栏里的可见性决定（`adminOnly` 生效）。
- **二级子页的四种承载方式与各自职责（2026-09-17 口径）**：① 侧边栏（浮窗）答"这个功能在哪"；② 顶栏中段答"同级页面切换"，与侧边栏同源；③ 页内 Tabs **只用于同一页面的取数范围/筛选**，且**必须落 search 参数**（例：我的 ASIN 的 `?view=items`，此前是组件内 `useState`，刷新即丢）；④ **页签栏答"这次工作里打开过哪些页面"**（2026-09-17 新增，可关闭、刷新保持）。四者不可互相替代：页签栏与 HeaderSlot 尤其容易被混为一谈（都长在顶栏附近），但前者是**历史**（跨模块、可关闭）、后者是**同级的并列切换**（同模块、常驻），所以两者**并存**，新增子页时按"是不是不同对象/不同任务"判断该放哪一层。
- **二级类目的呈现：桌面弹浮窗、移动端内联展开（2026-09-16 改）**：桌面端一级类目**不再内联手风琴展开**，改为**悬停或点击**时在右侧弹出浮窗（`SidebarMenuPopover`）；手机/平板（`isMobile`，抽屉式侧边栏）仍保留点击内联展开（触屏没有悬停，浮窗还会盖在抽屉上）。四个必须守住的实现点：① 浮窗**不能传 `tooltip`**（折叠成图标时 `SidebarMenuButton` 自带的 tooltip 会和浮窗叠在一起）；② **必须 `modal={false}`** —— 模态菜单打开时 Radix 会把 `body` 设为 `pointer-events: none` 并给侧边栏其余内容加 `aria-hidden`，菜单一开其它一级类目就既点不到也读不到（实测在浮窗打开状态下连「设置」按钮都无法被可访问性查询命中），非模态菜单下这些副作用都不存在；③ **点击一级类目后短窗内忽略关闭请求**（`CLOSE_GUARD`）—— 一次点击会连发两次 `onOpenChange(false)`（trigger 的 toggle + DismissableLayer 把它当成"点了菜单外部"），只忽略一次是不够的；④ **浮窗里不放一级类目标题**（2026-09-18 用户口径：「悬停在一级类目下展示二级类目时不需要展示一级类目的标题」）—— 去掉了原先第一行的 `DropdownMenuLabel`（标题 + 徽标）与分隔线，子项直接顶到第一行；标题与 `item.badge` 在触发按钮上本来就有，浮窗只需回答"这个类目下有哪些子页"，可访问名由触发按钮的 `aria-label` 提供（`DropdownMenuContent` 与它关联）。打开方式：悬停（`HOVER_OPEN_DELAY=120ms`，过滤鼠标扫过）、点击、键盘 Enter/空格；关闭方式：移开鼠标（`HOVER_CLOSE_DELAY=200ms`，指针移进浮窗会取消）、Esc、点击浮窗里的子项、点击别处；**再次点击同一入口也能收起**（2026-09-18 修正：此前 `handleOpenChange` 在按下后的时间窗里一律忽略关闭请求，导致"点开之后再点一下收不起来"；现在只忽略"尚未打开时"的关闭请求）。
- **侧边栏排版与状态口径（2026-09-18 统一，照此实现）**：
  - **行高网格（2026-09-20 收紧）**：一级项桌面端 **36px**（`h-9`，由 40px 收紧 —— 用户要求"一级类目紧凑一点"）、移动端抽屉 **44px**（`max-md:h-11`，**不跟着收紧**）、折叠成图标时 32px 方块（`group-data-[collapsible=icon]:size-8!`）；品牌区与底部用户区保持 **48px**（它们是区块、不是列表行）；浮窗子项 **36px**（`h-9`，与一级项同高 —— 父子层级改由浮窗面板自身承担）；分组小字 **24px 高 + 8px 上间距**（由 28px + 12px 压紧）。三区左内边距统一 16px，同域相邻项间距 4px（**不要压**：这是触屏相邻目标的可用性底线）。
  - **悬停与当前页必须分层**：悬停 = `bg-sidebar-accent/60`（临时反馈）；当前页 = `bg-sidebar-accent` + `text-sidebar-primary` + `font-semibold` —— **底色 + 主题色 + 字重三者共同表达**。此前两者都是 `bg-sidebar-accent`、只靠字重区分，鼠标扫过别的入口时当前页就"消失"了。
  - **侧边栏边缘（`SidebarRail`）用 `cursor-pointer`**：它只做"点击折叠 / 展开"，此前写成 `cursor-w-resize / e-resize`，暗示可以拖拽改宽度，而拖拽并不存在（控件语义必须与行为一致）。
  - **移动端抽屉必须有明确的关闭按钮**：`SheetContent` 自带的关闭按钮此前被 `[&>button]:hidden` 藏掉，只能点遮罩或按 Esc 退出；现在恢复显示（右上角、侧边栏配色），并给品牌区 `pe-11` 让位，否则这个绝对定位按钮会压在品牌名与 plan 文案上。
  - **移动端点击任何入口都要关抽屉**：一级项 / 二级子项 / 浮窗子项 / 底部「用户信息」都调 `setOpenMobile(false)`（`nav-user.tsx` 2026-09-18 补上，此前点完"用户信息"抽屉还盖在新页面上）。
  - **折叠成图标时隐藏子菜单箭头**：箭头在 32px 方块外会被 `overflow-hidden` 裁掉，视觉上看不见，但留在 DOM 里会污染"折叠态里有什么"的度量与自动化选择器。
- **当前一级类目清单（2026-09-18，按业务域分组）**：一级入口用 `section` 标注业务域，**同一层只表达同一种概念**（域 = 工作领域，一级项 = 该领域下的功能）：
  - **工作台**：仪表盘 `/`
  - **业务运营**：我的 ASIN `/asin-watchlists`、竞品分析（分析 `/competitor-analysis` ｜ 分析结果 `/competitor-analysis/results`）、产品开发（候选池 `/product-dev` ｜ 对比与历史 `/product-dev/compare` ｜ 市场调研 `/product-dev/market`，**带「开发中」徽标**）
  - **AI 工作台**：AI 助手 `/ai-agent`、提示词广场 `/prompts`、知识库 `/knowledge`
  - **系统管理**（管理员专属）：AI 治理 `/admin/ai`（`matchPrefix`）/ 用户管理 `/admin/users` / 公告管理 `/admin/announcements`
  **域的渲染规则**：同域只在第一次出现时渲染一次分组小字；**域标题与域里唯一一项同名时不渲染标题、改用一条分隔线**（2026-09-20 任务中心下线后，真实数据里已没有这种"同名单域"，该分支改由 `nav-group.test.tsx` 的构造数据守护）—— 否则侧边栏会连着出现两个同样的词，与 2026-09-18「系统管理」那轮的口径一致。
  其中**折叠类目 2 个**：「竞品分析」（分析 / 分析结果）、「产品开发」（候选池 / 对比与历史 / 市场调研）；其余都是直达叶子项。
  **「系统管理」只是分组标签**：它没有同名的可点类目（2026-09-18 前曾连出两次），三个治理入口各自平铺为一级项、逐个带 `adminOnly`（服务端每个接口另有 `requireAdmin` 兜底）。
  **个人入口不在 navItems 里**：用户信息 `/settings` 由右上角头像菜单与侧边栏底部进入 —— 个人设置与公司级治理不再同处一个类目。
  域的先后顺序 = "日常业务 → AI 工作台 → 管理员治理"；新增入口追加到所属业务域的语义位置。
- **占位类目（2026-09-15）**：未开发的能力可以占位，但必须满足两条 —— ① 入口**可点击并进入说明页**（历史上「任务中心」曾以这种形态存在，该板块已于 2026-09-20 整体下线），不做置灰死链接；② 用 `NavItem.badge`（如「开发中」）明确标注状态。**首页不允许出现同类占位卡片**（`仪表盘.md` 的"不展示伪功能"口径 + 测试断言守着），两者刻意不同：可点进的说明页不误导，首页的假卡片会误导。
- **「开发中」徽标也可以只表达对外状态（2026-09-18 用户口径）**：用户原话是把「任务中心」与「产品开发」一并标注为开发中（任务中心已于 2026-09-20 整体下线，现在只剩「产品开发」）—— 该板块的**入口与功能都是可用的**（三个子页各有真实路径），徽标在这里**不代表"点进去是说明页"**，只是状态标注。因此上一条"必须能点进说明页"不适用于这种用法；`src/components/layout/data/sidebar-data.ts` 的注释与 `server/verify-nav-ia.mjs` 的断言都写明了这条，改动或删除这个徽标前先与用户确认。
- **一级类目只保留一个入口，不要再挂回模块的二级导航**（2026-09-15，同日修正）：「提示词广场」在侧边栏是**一级类目**（`url: '/ai-agent/prompts'`）。它**曾经**也在 `agent-nav.tsx` 里作为「AI 助手」的第四项，同日按用户要求移除 —— 一级类目出现在别人的二级导航里等于自降一级，同一个入口还会在一屏内出现两遍。高亮由 `checkIsActive` 各判各的：`/ai-agent/prompts` 只点亮侧边栏那一项，不会连带点亮「AI 助手」折叠类目（折叠类目的子项里没有它）。
- **一级类目可以整页接管顶栏导航**（2026-09-15）：顶栏中段槽位（`HeaderSlot`）**由页面自己决定放什么**，不必然是所在模块的导航 —— `pages/layout.tsx` 按路径切换：`/ai-agent/prompts` 渲染 `prompt-square-nav.tsx`（提示词广场自己的两个子页：我的提示词 ｜ 共享提示词），其余子页仍渲染 `agent-nav.tsx`。理由：提示词广场已是侧边栏一级类目，顶栏再挂「对话 / 我的 ASIN / 我的沉淀」会让它看起来还是 AI 助手的子页。**这是本项目第一个"页面自己的顶栏导航不属于模块导航"的例子**，新增此类页面时照此办理（模块 layout 里按路径分流）。**同时必须给该路由声明 `staticData.title`**（`/ai-agent/prompts` 声明为「提示词广场」）：它不再继承模块级标题「AI 助手」，否则出现"顶栏标题说 AI 助手、导航却是提示词广场子页"的自相矛盾。
- **导航层级保持两级**：AI 治理整体收缩为 `/admin/ai`，**不挂三级菜单**；其四个子页由顶栏中段导航承载（`admin-ai-nav.tsx`；知识库 2026-09-18 移出治理面、并入「AI 工作台 → 知识库」）。侧边栏层级不随业务扩张而变深。**`/admin/ai` 是重定向入口（2026-09-16 起，落点 2026-09-18 改为 `/admin/ai/datasources`）**：索引路由 `beforeLoad` 直接跳到治理区内的第一项 —— 同名概览页已按需求删除、知识库也不再是治理子页，而侧边栏这一项的 url 就是 `/admin/ai`，**索引路由不能删**，删了入口就会落到 `notFoundComponent`。
- `NavItem.matchPrefix`：入口页在子页路径下保持高亮（如 `/admin/ai` 在 `/admin/ai/datasources` 下仍激活）。用显式字段而非对所有项做前缀匹配，避免 `/ai-agent` 连带点亮 `/ai-agent/notes`。
- **顶部栏是唯一的页面标题位**：页面名取自当前路由的 `staticData.title`，由 `pickPageTitle()` 从最深匹配往上找（子页未声明时继承模块级标题）。页面组件**不再**自己写标题横幅 —— 此前每个页面各写一份 `<Header>`，结果仪表盘漏写页面名、竞品分析的页面名在顶栏与内容区各写一遍，内容区那份还是 `text-2xl` 大字，占掉首屏约 116px。**2026-09-17 起这条由面包屑承载**：`pickPageTitle()` 从"渲染成单个 `h1`"改为"面包屑末级标题（导航里找不到同名项时的兜底）"，`usePageTitle()` 这个 hook 随之删除 —— 留一个没人用的 hook 只会让人以为顶栏还在渲染单标题。
- 顶部栏承载搜索、主题切换、用户信息入口，并有**常驻背景与底边框**（此前透明无边框，页面顶部看起来"悬空"，滚动后内容会从顶栏底下透出）。
- 顶部栏**全站 sticky**（`Header` 统一传 `fixed`），整页滚动与内容区内部滚动两种模式下都能常驻。
- **Header 中段槽位**：`HeaderSlot`（Portal）让模块把二级导航注入顶栏（AI 助手、AI 治理的四个治理页、知识库的两个子页），既省掉内容区一整行、又填掉顶栏中段原本近 1000px 的空白，还纠正了"导航压在页面标题之上"的层级倒置。

## 入口与出口

- 入口：`src/routes/_authenticated/route.tsx` 装配认证布局。
- 页面标题：各路由的 `staticData.title`；模块级路由（`/ai-agent`、`/admin/ai`）声明模块名，子页由导航高亮表达位置。
- Header 槽位：模块 layout 通过 `HeaderSlot` 注入 `agent-nav.tsx` / `admin-ai-nav.tsx`。
- 导航可见性：普通账号只看到非 `adminOnly` 的菜单项；具体路由另有各自的 `beforeLoad` 守卫、服务端接口另有 `adminGuard`，**侧边栏过滤只解决"看得见"**。
- 出口：子路由通过 `Outlet` 渲染到布局内容区。

## 影响范围

修改布局会影响所有登录后页面，包括仪表盘、设置中心和后续业务模块。修改侧边栏数据会影响导航入口、全局命令搜索可见性和用户访问路径。

**新增页面必须同步做两件事**：在路由上声明 `staticData: { title: '页面名' }`，否则顶栏不显示页面名（不报错，只是静默降级为只显示控件）；如果该页面属于带二级导航的模块，标题应声明在模块级路由上并由导航表达子页位置。工作台类页面（多栏同时开工）如需铺满宽度，再按需加 `staticData: { wide: true }` —— **不要因为"看起来空"就给普通内容页加**，那会回到 2026-09-11 已反转的"全部铺满"。

**面包屑与页签栏都挂在 `AuthenticatedLayout`（2026-09-17）**：前者由 `Header` 自己渲染，后者是与 `Header` 并列的一条通栏。这意味着**改这两处会同时影响全部 40+ 个登录后路由**，包括带动态参数的路由（`/competitor-analysis/$asin`）与 `adminOnly` 的治理页。验收口径见 `server/verify-page-shell.mjs`（24 项，跑在真实 Chrome 上），其中三条是最容易被后续改动破坏的：h1 仍然唯一、面包屑层级名与侧边栏同源、关掉当前标签必须离开那个页面。

`Header` 的 `h-16` 必须配合 `shrink-0`：`SidebarInset` 是 flex 纵向容器，`h-16` 只提供 flex-basis，内容区一高（AI 治理等长页面）就会把顶栏挤扁到 37px（实测过），而 Header 被压扁时页面首内容位置会被误判为"更紧凑"。

## 修改边界

- 可以改：布局组件内部展示、导航数据、菜单分组、顶部栏组合、响应式细节。
- 绝对不能动：无需求不得改变 `_authenticated` 路由结构、主题/字体/方向 Provider 的装配顺序、基础 shadcn/ui 组件实现。
- 不得让页面重新自己渲染 `Header`（会导致标题写两遍）；页面级操作走 `HeaderSlot`。

## 注意事项

- 当前 `_authenticated` 已接入本地会话守卫，但不代表真实服务端权限控制。
- 侧边栏和部分 UI 组件包含 RTL/项目定制，更新 shadcn 组件时需要人工合并。
- 内部工作台不展示付费升级、账单、新建团队、添加团队等 SaaS 模板入口。
- 侧边栏系统标识（`sidebar-data.ts` 的 `teams[0]`）名称固定为「JHYP 智能工作台」，副标题为「公司内部工作台」。
- 新增导航入口时，需要同步检查路由文件（含 `staticData.title`）和责任田文档；直接往 `sidebar-data.ts` 的 `navItems` 追加即可，侧边栏不再有"该归到哪一组"的问题。
- **新增页面后必须确认"有没有入口"**：判据是"从任意页面能否两步内到达"，不是"路由是否存在"。2026-09-15 盘点发现 `/settings/display`、`/settings/notifications` 两页存在已久却全站无入口（**同日确认这两页只是模板演示表单，已连同路由删除**），竞品分析与「我的 ASIN」则只有首页卡片 / 模块顶栏这一条路，已分别补上侧边栏一级类目。
- **全局行为挂在 `AuthenticatedLayout`，不要挂到页面上**：公告弹窗（`AnnouncementGate`）是第一个例子 —— 布局里挂一次，登录后自动生效、刷新不重复；挂到页面上会出现"漏挂的页面永远看不到"和"每页都挂各弹一次"两种毛病。挂新东西前先确认它是否该在这里，而不是顺手塞进某个页面。
- 顶栏槽位在窄屏可横向滚动（`no-scrollbar overflow-x-auto`），不换行 —— 槽位是固定高度容器，换行会撑破顶栏。
- **一级类目不再有"展开"箭头（2026-09-16 删除）**：此前「AI 助手」「设置」右侧各有一个 `ChevronRight`，用来表示"可以点开二级类目"。二级类目改成悬停/点击浮窗后这个箭头已名不副实（点它是弹浮窗，不是就地展开），按用户要求删除；**桌面与移动端一并删除**（移动端仍是点击内联展开，可展开的事实由"点击有反应"表达，不靠箭头）。**带子项的类目与叶子类目现在视觉一致**（都是「图标 + 标题」），这是有意接受的一致性代价 —— 需要区分时再看徽标（如「产品开发 开发中」）。
- **侧边栏展开态宽度：208px（13rem，2026-09-16 由 256px 收窄）**：`src/components/ui/sidebar.tsx` 的 `SIDEBAR_WIDTH` 是本项目定制值。用户提出"收窄 1/3 或 1/4"，实测两个候选都不可取 —— **1/3（≈171px）**会让最宽的导航项「产品开发 + 开发中」徽标放不下、文字折成两行；**1/4（192px）**类目仍单行但顶部品牌名被截断成「JHYP 智能工…」。**208px 是"类目名与品牌名都完整"的最窄值**（最宽那行还留约 28px 余量），相对原宽度收窄 48px（约 19%，约等于 1/5），1680 视口下内容区同步从 1416px 变宽到 1464px。改这个值时必须复验三件事：① 一级类目是否折行（判据用 `span.getClientRects().length > 1`，**不要**用按钮高度 —— `h-8` 高度固定，折行不会撑高它，只看高度会漏判）、② 顶部品牌区与底部用户区是否被截断、③ 折叠态 `SIDEBAR_WIDTH_ICON`（3rem，实际渲染 66px = 图标 + 内边距 + 2px）与移动端抽屉 `SIDEBAR_WIDTH_MOBILE`（18rem）不受影响。
- **侧边栏底部用户区已接入真实账号（2026-09-16）**：显示当前登录用户的**姓名 + 登录账号**，数据由 `AppSidebar` 注入（`/auth/me`，与「用户信息」页同一个 query key `['current-user']`，缓存共享；接口未回来时用登录态里的值，旧会话 cookie 没有 `name` 时退化成账号）。`sidebar-data.ts` 里那份 `user: { name: '内部用户', email: 'user@company.local' }` 的**硬编码假数据已删除**（连类型里的 `SidebarData['user']` 一起删），头像不再引用并不存在的 `/avatars/01.png`，改用姓名首字。**顶部头像（`ProfileDropdown`）仍是模板写死的 `SN` 占位**，尚未接入真实姓名——修它时照这里的做法（同一份 `/auth/me` 数据）。
