# 责任田：表格与列表规范

- **首次建立**：2026-09-15
- **归属**：横向能力（跨模块）。代码落在 `src/components/ui/table.tsx`（视觉基线）、`src/components/data-table.tsx`、`src/components/table-pagination.tsx`、`src/lib/table-styles.ts`。

## 功能描述

全站表格与列表的**统一外壳与分页口径**。

建立它的直接原因：审计 12 个表格文件 / 15 个表格实例时发现同一系统里表格有 8 类系统性差异 ——
外框 3 种、空态 4 种、加载态 3 种高度且 3 处「骨架与空态同屏」、数字列对齐只有 1 处正确而另 1 处反向过头
（给所有列无条件 `tabular-nums`）、操作列左右对齐与按钮形态各 3 种、分页器 `mt-3` 有写有没写、
默认 `pageSize` 20 与 50 并存、工具区位置 3 档、搜索框有物理类（`left-3`/`pl-9`，RTL 下错位）与逻辑类两套。

## 视觉口径（2026-09-16 统一，改前各表"表头与数据行同白底同字号"）

台账类表格的可读性靠**表头 → 数据行 → 次要信息**三级层次，而不是靠加边框、加阴影。三级全部落在
`src/components/ui/table.tsx` 的基类上，各页**不要再逐表写这些类**：

| 层级 | 规格 | 落点 |
| --- | --- | --- |
| 表头 | `bg-muted` 实色底 + `text-xs text-muted-foreground font-medium` + `h-9` | `TableHead` |
| 数据行 | 14px `text-foreground`、`py-2.5`（单行约 40px）、`hover:bg-muted/50` | `TableCell` / `TableRow` |
| 次要信息 | `TABLE_CELL_META`（`text-xs text-muted-foreground`） | 各页列 |
| 首末列留白 | `px-3` + `first:ps-4 last:pe-4`（两端各 16px） | `TableHead` / `TableCell` |
| 数字列 | `TABLE_HEAD_NUMERIC` + `TABLE_CELL_NUMERIC` **成对出现** | 各页列 |

三条硬理由（改前踩过的）：

- **表头底色用实色 `bg-muted`，不用 `bg-muted/60`**：吸顶表头随滚动压在数据行之上，半透明底色会让滚过的行透出来。
- **`TableHead` 不能再带 `text-foreground`**：可排序表头里的 `<button>` 会继承它，那一列表头会比其它列重。
- **表头字号降到 `text-xs` 后，列名里的图标按钮（排序、帮助）也继承 12px**：这是有意的 —— 列名是坐标不是数据；行内数据仍是 14px，视觉主体不变。

## 分页口径

- **服务端分页优先**：会长期累积的列表一律走服务端 `page`/`pageSize`，并在同一组筛选条件下返回 `total`。
  统一入口是 `server/ai-agent/http-utils.mjs` 的 `parsePageQuery()`（`page` 默认 1、`pageSize` 默认 20、**上限 100**）。
- **前端切片只在满足两个条件时使用**：① 数据有明确且不大的上限；② 筛选逻辑本来就在前端。
  典型例子是用户管理（`/api/users` 返回全量、`filterUsers()` 已有单测）—— 此时切片必须发生在**筛选之后**
  （「先筛后排再分页」），否则会出现"筛选结果只有当前页那几条"。
- **不能用截断代替分页**：会话列表此前是 `LIMIT 100` 且不返回总数，第 101 条起静默不可见。
  截断必须换成 `page`/`pageSize` + `total`。
- **导出与列表共用同一组筛选条件**，且导出另有独立上限（不要用分页参数去限制导出）。
- **形态选择**：表格与卡片网格用 `TablePagination`；**滚动的分组时间轴**（工作台左栏会话列表）用
  「加载更多」累积分页（`useInfiniteConversations`），把带页码与"每页条数"的分页器嵌进时间轴既占高度、
  也和分组语义打架。
- **表格与卡片可切换时，默认值按"这批数据的读法"定**：竞品分析的商品数据是"带主图的选品对象"
  （默认卡片、可切表格）；**提示词广场于 2026-09-17 按用户口径「提示词广场使用卡片展示」改回默认卡片**
  （此前 2026-09-16 曾按"内容优先用表格"设为默认表格）—— 一条提示词要读的是
  名称 / 创建人 / 使用次数 / 正文四件事，卡片能一起摆开，表格则把每条压成一行、完整正文要点「查看全文」；
  **表格仍是可切换视图，没有删除**（需要按状态 / 更新于 / 使用次数横向比对时表格更合适）。
  切换控件用 `aria-pressed` 的分段按钮（不是选项卡：同一批数据的两种读法，与页面级子页不是一回事），
  偏好存 `localStorage`、读失败回落默认值。**默认值口径变更时偏好键要一并换版本**
  （提示词广场用的是 `prompt-square-layout:v2`）：沿用旧键会让存过旧默认的浏览器停在已废弃的默认上，
  看起来像改动没生效。
- **长内容不要用"展开"撑开容器，改用弹窗**（2026-09-17，来自提示词广场"点击卡片后以弹窗的方式呈现而不是拉长"）：
  卡片网格里的"展开"会让该卡跨列变高，而卡片等高靠 `auto-rows-fr` 保证 —— 一张卡变高会把**同页其余卡片一起顶高**、
  点开一次整页跳动；表格里的"在该行下方插一行"则会把行高撑成几百像素、行序也不再整齐。
  两种形态统一改为**点开一个只读详情弹窗**（`Dialog` + 固定高度内滚动），容器尺寸恒定。
  **整卡可点时按数据源卡片的既有形态**（`role='button'` + `tabIndex` + `Enter/Space`），
  两个必须的防御：内部按钮所在容器 `onClick` 里 `stopPropagation()`（否则点「删除」会顺带弹详情），
  以及按键处理器里 `event.target !== event.currentTarget` 就返回（焦点在内部按钮上按 Enter 时 keydown 同样会冒泡上来）。
  「查看全文」这类字样在整卡已是按钮时**只做视觉提示（`span`）**，不要再套一层同名按钮 —— 读屏会遇到两个重叠的可点区域。

## 注意事项

- **加载态必须与空态互斥（2026-09-15，踩过）**：迁移前有 3 处表格同时渲染骨架与"没有匹配的记录"
  （`audit-console` 两张表、`datasource-management`）。`DataTable` 里 `isLoading` 优先于 `isEmpty`，
  调用方不要再自己写 `{isLoading && <Skeleton/>}` 三元。
- **不要在 effect 里同步 setState 修页码（2026-09-15，踩过）**：页码越界（审核后队列变短、删掉本页最后一条）
  曾用 `useEffect` 回写 `setPage`，被本仓库 eslint 的 `react-hooks/set-state-in-effect` 直接拦下 ——
  该规则是对的，那条 effect 还会多一次级联渲染。现行做法：
  ① `TablePagination` 内部**只夹紧显示**（`currentPage = Math.min(page, totalPages)`）与翻页按钮可用性；
  ② 数据变少的动作在自己的成功回调里回退页码（如审核通过后 `setPage(1)`）。
- **列语义常量只解决"同类列写法一致"，不解决"该不该是数字列"**：迁移时逐列判断过 ——
  耗时、token、切片数、行数是数字列；时间、来源、账号、备注是次要信息（`TABLE_CELL_META`）；
  拦截原因等告警文本必须保留 `text-destructive`，**不能**被 `TABLE_CELL_META` 的 muted 吃掉。
- **`TABLE_CELL_TRUNCATE` 必须配 `title` 兜底**：截断后看不到原文等于信息丢失。
  刻意不截断的列（如导入失败原因）保留 `break-words` 换行，不要为了"统一"改成截断。
- **工具区位置不强求统一**：页面级筛选条（同时作用于同一页面多个区块，如知识库顶部的状态/来源筛选）
  保持原位；只有"属于这张表"的搜索与批量操作才放进 `toolbar`。
- **`pageSize` 上限 100 是服务端硬顶**：`TablePagination` 的每页选项（10/20/50/100）与之对齐，
  再往上加会得到被服务端悄悄夹回 100 的页 —— 那时页数与总数就对不上了。
- **分页字段与角标字段不是一回事**：提示词审核接口同时返回 `total`（当前筛选下的总条数）与
  `pendingTotal`（待审总数，与筛选无关），两者不可互相替代。
- **跳页是可选的、按量级开（2026-09-16）**：`jumpTo` 默认关闭。判断标准是总页数的量级 ——
  几十页以内翻页按钮够用，而 ASIN 清单（5000 条 / 每页 50 = **100 页**）没有跳页就只能逐页点。
  开启后它只在 `totalPages > 1` 时渲染；输入非法（空 / 非数字 / 越界）一律**丢弃草稿**而不是
  "猜一个接近的页码"，提交前夹紧到 `[1, totalPages]` —— 与"分页器只夹紧显示、不回写调用方 state"
  的既有口径保持一致（回写会在 `react-hooks/set-state-in-effect` 上翻车，见上一条）。
- **`stickyHeader` 曾完全不生效，2026-09-16 已在 `DataTable` 内局部修好**：`sticky top-0` 加在 `<thead>` 上，
  但表格是 `border-collapse: collapse`（Tailwind preflight 的默认值），Chromium 在该模式下不认 thead 的
  `position: sticky` —— 实测滚动 240px 后 `thead.getBoundingClientRect().top` 从容器顶 256px 掉到 16px，
  也就是**表头跟着滚走了**。受影响的是三处传了 `stickyHeader` 的表：ASIN 清单条目表、
  弹窗内数据集行表、提示词广场长表。
  修法（**三件事缺一不可，第二层最容易漏**）：
  ① `border-collapse` 换成 `separate` + `border-spacing-0`；
  ② 行线从 `<tr>` 迁到单元格（separate 模式下 `<tr>` 的 border 不渲染）——
  `[&_tr>*]:border-b` + 末行 `[&_tbody_tr:last-child>*]:border-b-0`；
  ③ **让开 `Table` 自带的那层 `overflow-x-auto` 包裹**（`ui/table.tsx`）：`overflow-x: auto` 会让
  `overflow-y` 也算成 `auto`，于是这层成了**最近的可滚动祖先**，thead 的 sticky 相对它定位、
  而它自己不纵向滚动、只跟着外层滚走 —— 只做完 ①② 时实测 `stuck` 依然是 `false`（滚动 240px 表头照掉）。
  做法是在外层滚动容器上加 `[&>div]:overflow-visible`（仅当 `stickyHeader` 与 `maxHeightClass` 同时存在：
  没有限高时外层不滚，内层必须保留 overflow-x）。
  **改动是局部的**：只在传了 `stickyHeader` 的表上生效，其余表格的 DOM 与视觉零变化；
  全站行线口径的变更仍留给基座 `ui/table.tsx` 单独一轮。
  验证：`node verify-artifacts/table-ux-sticky.mjs` 由 `stuck: false` → **`stuck: true`**
  （滚动 240px 后 thead 的 top 保持 256，`tableBorderCollapse` 显示 `separate`）。

## 约束

- 必须复用：`DataTable`（不新写表内外框与空态/加载态）、`TablePagination`（不手写"上一页/下一页"）、
  `src/lib/table-styles.ts` 的列语义常量（不散落字面量 `text-right tabular-nums` / `font-mono text-xs`）、
  **`ListPageShell` + `ListSearchInput`**（列表页工具区的两排结构；不要再自己拼 `flex` 排搜索框与按钮组）。
- 新增表格时：`columns` 必须等于 `header` 里 `TableHead` 的数量；空态文案要区分"有无筛选条件"。
- **行多选走 `use-row-selection`**：它刻意只在**当前页内**选择，因此调用方在翻页、改筛选、
  改每页条数时都要 `clear()`（用户管理页的 `changePage()` 是现成范例）。
  批量动作若会影响他人（如批量停用账号），必须走 `ConfirmDialog` 二次确认，
  并且**未勾选时把按钮置灰 + 在 `title` 上写明禁用原因**。
- 验证要求：`pnpm run lint`、`pnpm exec tsc -b`、`pnpm run build`、`pnpm run test:server`；
  页面级回归按各模块责任田的验收脚本跑。
- **视觉类改动额外要求**：改 `ui/table.tsx` 后跑 `node verify-artifacts/table-ux-shots.mjs <前缀>`
  截「用户管理 / 公告 / 知识库 / ASIN / 审计台 / 产品开发」六个页面，并加 `--dark` 再截一套深色
  （主题存在 cookie `vite-ui-theme`，脚本已内置切换）；浅色深色都确认表头层次、行线、列对齐后才算完成。
