# 责任田：仪表盘

## 功能描述

负责登录后首页（`/`）的个人工作台：快速进入真实业务、查看自己的 AI 使用状态与最近活动。

首页只承担工作台职责：**不展示 AI 治理内容**（知识库、数据源、经验审核、模型配置、审计台），**不展示没有路由或没有数据支撑的伪功能**（历史版本出现过「即将上线」的占位卡片）。治理入口保持在管理员侧的「AI 治理」导航分组。

## 功能清单

- 常用入口：四个有真实路由的入口，支持拖拽排序与键盘排序，顺序持久化。
- 入口卡片：桌面端四列、平板端两列、移动端一列；卡片高度由 `min-h-40` 统一；图标/名称/说明三层结构，图标用 `lucide-react`。
- 工作动态：桌面端 7:5 分栏 —— 左侧「我的 AI」（最近 3 条对话 + 沉淀总数与待审核数），右侧「最近活动」（最近竞品分析记录）；移动端纵向排列。
  - 为什么换掉原来的「正在进行的工作」：它读的 `work_items` 表只由竞品分析写入**一条 progress 固定 65 的假任务**，全仓库没有任何更新入口（实测库里 0 行）—— 界面长期是空态，一旦产生又永远挂着、也清不掉；与此同时首页完全不体现项目的真实使用重心（AI 问答与知识沉淀）。该表已停止写入，首页也不再读取它。
- 状态处理：查询中用 `Skeleton`；查询失败给出「重新加载」按钮并可重试；空数据展示明确空态且不隐藏区域；排序保存失败保留本地顺序并 toast 提示。
- 可访问性：拖拽不是唯一排序方式（每张卡片有带 `aria-label` 的上移/下移按钮，首尾自动禁用）；顺序变化用 `aria-live` 播报；装饰性图标一律 `aria-hidden`。
- **无页面标题横幅**：页面名「仪表盘」由全局 `Header` 从路由 `staticData.title` 渲染。改造前这里有一个 `text-2xl` 的 h1「JHYP 智能工作台」加一句口号，占掉首屏两行，且它只是应用名/口号、不是内容重点。

| ID | 名称 | 路由 |
| --- | --- | --- |
| `ai-chat` | AI 助手 | `/ai-agent` |
| `quick-navigation` | 快捷导航 | `/quick-navigation` |

**ID 变化**：历史版本的 `project` / `listing` / `reviews` 三个占位 ID 已下线（无路由、无数据，会渲染成「即将上线」的假卡片）。

## 旧偏好兼容策略

数据库里可能仍存着历史用户的旧 `shortcut_ids`。归一化由前端 `normalizeShortcutIds`（`src/features/dashboard/shortcuts.ts`）负责，规则为：

1. 丢弃无法识别的 ID；
2. 丢弃重复 ID，保留首次出现的位置；
3. 保留仍然有效的 ID 的原有相对顺序；
4. 缺失的入口按默认顺序追加到末尾；
5. 因此无论输入多脏（空数组、非数组、只剩旧 ID），结果恒为四个有效入口。

不做数据迁移、不删除既有用户偏好：旧记录经归一化后即可正常渲染，用户下次调整顺序时会写回新 ID。

## 入口与出口

- 入口：`src/routes/_authenticated/index.tsx`。
- 出口：`/ai-agent`、`/ai-agent/notes`、`/quick-navigation`、`/competitor-analysis`。

## API 明细

- `GET /api/dashboard`：返回 `workItems`、`shortcutIds`（入口顺序，可能是历史 ID）、`analyses`（最近 5 条竞品分析）。其中 `workItems` **首页已不再读取**，服务端保留该字段只为不破坏既有响应契约。
- `PUT /api/dashboard/shortcuts`：保存当前用户入口顺序。
- `GET /api/ai/conversations`：「我的 AI」的最近对话（取前 3 条）。员工可读接口，不需要管理员权限。
- `GET /api/ai/notes?page=1&pageSize=1`（可带 `status=pending`）：首页只取响应里的 `total`，用于「共 N 条 / M 条待审核」。用 `pageSize=1` 是为了让服务端少读数据。
- 服务端在没有偏好记录时返回 `server/dashboard-shortcuts.mjs` 的默认顺序。

## 依赖关系

- 依赖：`src/components/layout/`、`src/components/ui/`、`src/features/dashboard/shortcuts.ts`、React Query 与 `src/api/client`。
- 被依赖：全局首页路由和后台默认入口。
- 共享字段：`shortcutIds` 的默认顺序同时存在于服务端（`server/dashboard-shortcuts.mjs`）与前端（`src/features/dashboard/shortcuts.ts`）。改一处必须同步改另一处，否则新用户的首屏顺序会与前端定义的默认顺序不一致。两处都有单测守住「只含四个真实入口、不含已下线占位 ID」。

## 影响范围

修改仪表盘可能影响首页首屏信息结构、主题适配和移动端布局。首页是登录后默认落地页，改动会影响所有角色的第一印象。

列表渲染需注意：工作动态区域的 grid item 必须带 `min-w-0`。grid item 默认 `min-width: auto`、列宽又是 `1fr`（最小值为 auto），一旦列表里出现 `truncate` 的长标题就会把整列撑宽、把页面顶出横向滚动（已由 `index.test.tsx` 的横向溢出断言守住）。

## 修改边界

- 可以改：仪表盘内部卡片、分区组件、空态、加载态、错误态和入口定义。
- 绝对不能动：无需求不得修改全局布局、认证路由分组、主题变量命名和其他模块页面结构。
- 不得把 AI 治理内容（知识库、数据源、经验审核、模型配置、审计台）放进首页，也不得在首页新增经营指标类伪数据。

## 注意事项

- 当前是内部工作台首页，不展示模板销售、收入、订阅等伪数据。
- 入口卡片只放有真实路由、有真实数据的入口；新增入口前先确认路由存在。
- 排序保存失败时**不能**让顺序回退：`pendingOrder` 保留用户的本地顺序，只提示失败。
- 保存成功后不清空 `pendingOrder`，否则界面会在重新拉取完成前闪回旧顺序。
- 拖拽只从卡片主体（`Link`）发起，避免按住排序按钮时误触发拖动。
- 组件按分区拆分：`index.tsx` 内保留 `ShortcutSection` / `ShortcutCard` / `RecentActivityCard` / `DashboardEmpty` / `DashboardRetry`，纯逻辑与入口契约在 `shortcuts.ts`、类型在 `types.ts`、新卡片在独立文件 `my-ai-card.tsx`（它自己要打三个接口，放在一起会让 `index.tsx` 过于臃肿）。
- 「我的 AI」的文案不要出现治理面词汇（知识库、数据源、经验审核、模型配置、审计台）：`index.test.tsx` 有守护断言。

## 约束

- 必须复用：`Header`、`Main`、`Search`、`ThemeSwitch`、`ProfileDropdown`、shadcn/ui Card / Button / Badge / Skeleton。
- 验证要求：代码修改后运行 `pnpm run lint`、`pnpm run build`、`pnpm run test:server`，以及仪表盘前端测试（`src/features/dashboard/`）。
- 本机缺 Playwright Chromium，`pnpm run test` 跑不起来时的替代方式见 `docs/用户信息只读化-交接文档.md` 的「环境备忘」。
