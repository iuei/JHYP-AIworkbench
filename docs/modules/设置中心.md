# 责任田：设置中心

## 功能描述

负责用户设置区域，包括统一用户信息、用户管理、外观设置页及其全局侧边栏导航入口。

## 功能清单

- 设置入口：展示设置页框架和子路由出口。
- 标题层级：设置路由壳不展示固定标题，由当前子页面提供唯一页面标题和说明。
- 用户信息：在 `/settings` 同一页面维护个人资料、账户信息和退出登录操作。
- 用户信息布局：桌面端双栏展示个人资料与账户信息，登录与安全横跨底部；移动端使用单列。
- 用户管理：提供用户列表、搜索筛选、账号开通、账号关闭和状态展示的前端管理入口。
- 外观设置：维护主题、字体等外观选项。
- 设置导航：由全局侧边栏“设置”一级菜单提供用户管理和外观入口；用户信息由侧栏底部用户区域和顶部头像进入。

## 入口与出口

- 入口：`src/routes/_authenticated/settings/route.tsx` 和子路由。
- 出口：设置中心内部通过子路由切换不同设置页面。

## API 明细

- 暂无真实 API，当前以表单和用户列表演示交互为主；用户管理暂未接入服务端鉴权、审计和会话失效能力。

## 依赖关系

- 依赖：`src/features/settings/`、`src/components/ui/`、`react-hook-form`、`zod`、主题/字体 Context。
- 被依赖：后台设置菜单入口和用户偏好配置。
- 共享字段：主题、字体等偏好会影响全局界面。

## 影响范围

修改设置中心可能影响用户偏好、主题表现、字体表现、设置页路由和全局 Cookie 持久化。外观设置属于横向能力，可能牵动全部页面。用户管理入口会影响设置中心内部导航和账号生命周期管理展示，但当前不改变真实权限或后端数据。

## 修改边界

- 可以改：设置页内部表单、设置侧栏、设置页面文案、用户管理前端演示数据和校验。
- 绝对不能动：无确认不得改变全局主题 token、字体资源、Cookie key、Context Provider 装配顺序。

## 注意事项

- 设置类页面应沿用 `Settings + Outlet` 结构。
- 设置页仅承载标题和子路由内容；设置项跳转统一由全局侧边栏提供。
- 用户管理当前仅为前端演示数据；真实接入时，开通、关闭、锁定和角色变更必须走服务端权限校验与审计。
- 表单提交当前多为演示逻辑，真实接口接入前不能硬编码成功状态掩盖缺失 API。
- 通知和显示设置当前不从设置导航暴露，后续有真实通知或导航配置需求时再恢复。
- `/settings/account` 仅作为旧入口保留，访问时重定向到统一的 `/settings` 用户信息页。

## 约束

- 必须复用：`ContentSection`、shadcn/ui Form、主题与字体 Context。
- 验证要求：代码修改后运行 `pnpm run lint`、`pnpm run build`，设置项修改需手动验证持久化和刷新恢复。
