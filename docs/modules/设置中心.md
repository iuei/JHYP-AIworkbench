# 责任田：设置中心

## 功能描述

负责用户设置区域，包括统一用户信息、用户管理及其全局侧边栏导航入口。

## 功能清单

- 设置入口：展示设置页框架和子路由出口。
- 标题层级：**页面名统一由全局 `Header` 从路由 `staticData.title` 渲染**（`/settings` → 用户信息、`/settings/users` → 用户管理）；设置路由壳与 `ContentSection` 都不再渲染标题与分隔线。
- 用户信息：在 `/settings` 只读展示当前账号的登录账号、姓名、部门和角色，并提供退出登录操作。
- 用户信息只读边界：姓名、部门和角色由管理员在用户管理中配置，用户无自助编辑入口；页面数据取 `GET /api/auth/me`。
- 用户信息布局：桌面端双栏展示只读字段，登录与安全独立成段；移动端使用单列。
- 用户管理：提供用户列表、搜索筛选、账号开通、账号关闭和状态展示的前端管理入口，并维护部门字段。
- **外观设置页已删除（2026-09-15）**：`/settings/appearance` 只有主题与字体两个表单，内容过少且无人使用（主题切换在顶栏常驻），按需求移除页面、路由、feature 目录与侧边栏入口。**主题切换保留在顶栏头像左侧的 `ThemeSwitch`**，字体由 `FontProvider` 继续应用。
- 设置导航：由全局侧边栏「设置」一级菜单提供「用户管理」「公告管理」「AI 治理」（三项均 `adminOnly`）；用户信息由顶部头像（`ProfileDropdown` 的「用户信息」）进入 `/settings`。**普通账号的侧边栏不会出现「设置」分组**（子项被 `nav-filter.ts` 过滤空后整组移除），管理员不受影响。

## 入口与出口

- 入口：`src/routes/_authenticated/settings/route.tsx` 和子路由。
- 出口：设置中心内部通过子路由切换不同设置页面。

## API 明细

- `GET /api/auth/me`：用户信息页只读展示的数据来源（返回 `id / login / name / role / department`），不接受任何写入。
- 部门字段的新增与修改走管理员侧 `POST /api/users` 与 `PATCH /api/users/:id`，不是用户自助接口。

## 依赖关系

- 依赖：`src/features/settings/`、`src/components/ui/`、`react-hook-form`、`zod`、React Query、主题/字体 Context。
- 被依赖：后台设置菜单入口和用户偏好配置。
- 共享字段：主题、字体等偏好会影响全局界面；角色文案由 `src/features/settings/user-labels.ts` 统一提供。

## 影响范围

修改设置中心可能影响用户偏好、主题表现、字体表现、设置页路由和全局 Cookie 持久化。用户管理入口会影响设置中心内部导航和账号生命周期管理展示。

> 删掉「外观」页后，`/settings/appearance` 不再有路由，旧书签由根路由的 `notFoundComponent` 兜底渲染「Not Found」（实测确认，不是白屏）。设置页的路由集合在 2026-09-15 再收敛为 **`/settings`（用户信息）、`/settings/users`（用户管理，仅管理员）、`/settings/announcements`（公告管理，仅管理员）** 三项 —— 「显示」「通知」两页随其演示表单一并删除（见「历史变更」）；`account` 仅作为旧入口保留并在访问时重定向到 `/settings`。删除的 `/settings/display`、`/settings/notifications` 与 `appearance` 同样是 `notFoundComponent` 兜底，不是白屏。
>
> **`/settings/announcements` 的归属（2026-09-15 补）**：页面实现在 `src/features/announcements/`，只借用设置中心的路由壳与 `ContentSection` 外壳，责任田在 `公告.md`（含登录弹窗、数据表与接口）。改这一页时读那份文档，不要按"设置中心子页"的口径改。
>
> **侧边栏「设置」类目的现状（2026-09-15 定稿）**：类目下只剩「用户管理」「公告管理」「AI 治理」三项，**全部是 `adminOnly`**，因此普通账号的侧边栏不会出现「设置」分组（空分组被 `nav-filter.ts` 移除）。员工侧的「用户信息」只从右上角头像菜单进入 `/settings`（`nav-user.tsx` 与 `profile-dropdown.tsx`）。历史上曾把「显示」「通知」补进该类目以获得一个非 admin 子项，但那两页是纯演示表单，同日已删除，**不再作为保留该类目的理由**。

用户信息页的只读展示依赖 `GET /api/auth/me` 的字段契约：新增或改名返回字段时，必须同步 `src/features/settings/profile/types.ts`，否则只读区会静默显示空白。

## 修改边界

- 可以改：设置页内部表单、设置侧栏、设置页面文案、用户管理前端演示数据和校验。
- 绝对不能动：无确认不得改变全局主题 token、字体资源、Cookie key、Context Provider 装配顺序。
- 禁止把管理员配置项（姓名、部门、角色）再做成用户可自助编辑的表单；用户侧只能只读展示。

## 注意事项

- 设置类页面应沿用 `Settings + Outlet` 结构。
- 设置页仅承载标题和子路由内容；设置项跳转统一由全局侧边栏提供。
- 用户管理已接入真实服务端接口；开通、关闭、锁定和角色变更必须走服务端权限校验与审计。
- **用户信息页不得写回数据**：此前 `/settings` 的个人资料与账户信息表单只调用 `showSubmittedData`（弹 JSON toast），无接口、不落库，却让用户以为能改工号（账号主键）和角色（权限依据），属职责错位加权限误导，已于 2026-09-11 移除。
- 部门是管理员配置字段，落在 `users.department`（迁移 version 2），用户侧只读；`PATCH /api/users/:id` 未携带该字段时保留原值，显式传空串才是清空。
- **外观设置页已删除（2026-09-15）**：主题仍由顶栏 `ThemeSwitch` 写入 `ThemeProvider`（cookie 持久化），字体仍由 `FontProvider` 应用；`src/config/fonts.ts` 的名单保留给 Provider 取值校验与默认字体，界面不再提供字体切换入口。删除前该表单每次提交都会弹 `showSubmittedData` 演示提示，属遗留噪音，随页面一并消失。
- **「显示」「通知」两页已删除（2026-09-15）**：两页是 shadcn 模板遗留的**纯演示表单**（显示页 = "最近/首页/应用/桌面/下载/文档"复选框组，通知页 = 通知类型单选 + 邮件开关组），提交只调 `showSubmittedData`，无接口、无数据、与本站业务无关 —— 用户确认"功能重叠实用性不大"。**删的是页面与路由，不是隐藏入口**：`src/routes/_authenticated/settings/{display,notifications}.tsx` 与 `src/features/settings/{display,notifications}/` 均已删除，侧边栏两项同步移除。将来若真有通知偏好或导航配置需求，按新需求重建，不要恢复这两个演示表单。
- `/settings/account` 仅作为旧入口保留，访问时重定向到统一的 `/settings` 用户信息页。

## 约束

- 必须复用：`ContentSection`、shadcn/ui Form、主题与字体 Context。
- 验证要求：代码修改后运行 `pnpm run lint`、`pnpm run build`，设置项修改需手动验证持久化和刷新恢复。
