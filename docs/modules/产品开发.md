# 责任田：产品开发

面向**上架前的候选新品**：把候选产品沉淀成可检索的池子，支持多个候选横向对比，并把对比结果保存下来供回看。

数据是**双轨**的 —— 候选的身份与选品字段（价格、评分、评论数等）由**人工录入或表格导入**，
经营表现指标（广告、销售）来自**本公司已导入的 Amazon 报表**。两轨在对比结果里分开标注来源，
绝不混成一套数字。

## 功能描述

解决的是"选品调研无处落脚"这一缺口：业务已有《新品开发流程（产品开发系统 v1.0）》，
其中「选品调研」是立项后的必经节点，但平台此前没有任何承载 —— 候选产品无处存、
候选之间无从对比、调研结论无法沉淀，运营只能在 Excel 里手工维护。

本模块与相邻模块的对象和时机不同，**不是竞品分析的第二版**：

| 模块 | 对象 | 时机 |
| --- | --- | --- |
| ASIN 清单 | 我已上架的 ASIN | 上架后，持续监控 |
| 竞品分析 | 手输的 1–5 个 ASIN | 任意时刻，即时横比 |
| **产品开发（候选池）** | **候选新品** | **上架前，决策与沉淀** |
| **产品开发（市场调研）** | **一个类目**（不看任何单个 ASIN） | **选品阶段，判断值不值得进** |

**候选池与市场调研为什么同属本模块**：两者都在"上架前"这个阶段用，都是选品调研的组成；
但**分析对象完全不同** —— 候选池的对象是"我录入的候选"，市场调研的对象是"类目本身"。
市场调研**不需要 ASIN**（选品时往往还没有），这正是它不能留在竞品分析页的原因
（那边输入的是 ASIN 列表，此前只能从本品详情里蹭一个类目节点出来）。

## 功能清单

- 候选产品池：新建 / 编辑 / 软删，字段为 `marketplace`、`asin`、`product_name`、`category`、
  `target_price`、`stage`、`note`，**其余字段一律进 `attributes JSONB`**
- 检索：按关键词（产品名称 / ASIN / 类目 / 备注）、站点、阶段筛选 + 分页
- 表格导入：粘贴或上传 CSV / XLSX，**先预览后确认**（预览显示识别到哪些列、会新增多少、
  哪些行读不出来、前 5 条样例），四分类反馈 `added` / `duplicated` / `repeated` / `invalid`
- 横向对比：勾选 2–10 个候选 → 按「人工录入维度 + 我方报表指标」双轨生成对比表 → 保存快照
- 对比历史：列表 + 单条回看（读快照，不用今天的数据重算）
- **市场调研（2026-09-16 新增，2026-09-22 增加报告快照）**：按关键词搜类目（卖家精灵 `product_node`）→ 选中类目 →
  产出市场规模（月销量/销售额/在售商品数/品牌数与卖家数）、集中度（TOP3/5/10/20 商品·品牌·卖家）、
  新品结构（近 1/3/6/12 个月占比与表现）、价格带分布，并给出确定性「市场判断」结论；
  结果里附该市场 TOP 商品 ASIN（可一键带到竞品分析逐个对比），支持保存为账号私有报告并在历史记录中回看

## 入口与出口

- 入口：侧边栏**折叠类目**「产品开发」，三个子页各有真实路径（2026-09-16 阶段 B）：
  - 候选池 `/_authenticated/product-dev`（本模块默认子页）
  - 对比与历史 `/_authenticated/product-dev/compare`
  - 市场调研 `/_authenticated/product-dev/market`（可带 `?keyword=` / `?marketplace=` 进入，竞品分析页的跳转用）
- 出口：三个子页由**顶栏中段导航**（`ProductDevNav`，与侧边栏子项同源派生）互相切换；
  市场调研结果里的 TOP 商品 ASIN 可带到竞品分析逐个对比
- **旧链接兼容**：`?view=market` / `?view=compare` 是阶段 B 之前的页签参数，在候选池路由的
  `beforeLoad` 里重定向到新路径（`keyword` / `marketplace` 一并透传）
- **跨子页状态**（选中候选、对比区间、对比结果）由模块布局 `ProductDevLayout` 持有并经
  `ProductDevContext` 注入（见「注意事项」）；候选列表与对比历史两个查询**不上提** ——
  React Query 缓存本来就跨组件共享，子页各自 `useQuery` 不会重复请求

## API 明细

全部挂在 `/api/product-dev` 下，走 `requireUser` + 本人数据隔离（**无管理员后门**：
管理员访问他人候选同样 404，与 ASIN 清单、知识沉淀的所有者视角一致）。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/product-dev/candidates` | 检索候选池（关键词 / 站点 / 阶段 / 分页） |
| GET | `/api/product-dev/candidates/:id` | 单条详情 |
| POST | `/api/product-dev/candidates` | 新建候选 |
| PATCH | `/api/product-dev/candidates/:id` | 编辑候选 |
| DELETE | `/api/product-dev/candidates/:id` | 软删候选 |
| POST | `/api/product-dev/candidates/import` | 表格导入（`?dryRun=true` 只预览、不写库） |
| POST | `/api/product-dev/comparisons` | 发起对比（返回结果 + 落库快照） |
| GET | `/api/product-dev/comparisons` | 对比历史列表（只回摘要，不回快照） |
| GET | `/api/product-dev/comparisons/:id` | 单条对比（含快照），越权 404 |
| DELETE | `/api/product-dev/comparisons/:id` | 删除对比记录 |
| GET | `/api/product-dev/market/categories?keyword=&marketplace=` | **市场调研：按关键词搜类目节点**（1 次卖家精灵调用，24h 缓存）；返回候选类目（含在售商品数与 `nodeIdPath`） |
| POST | `/api/product-dev/market/analyze` | **市场调研：类目市场结构分析**（固定 2 次调用：市场规模 + 价格带分布）；body `{ marketplace, nodeIdPath, nodeLabel?, refresh?, publicTtlHours? }`；返回 `{ result: { headline, findings, findingLevel, blocks, market, topAsins, meta } }`（`meta` 含 `calls` / `cacheHits` / `errors`） |
| GET | `/api/market-insights/reports` | **市场报告：查询当前账号的报告摘要**；支持 `marketplace` / `limit` |
| POST | `/api/market-insights/reports` | **市场报告：保存冻结快照**；body `{ marketplace, scopeType, scopeKey, scopeLabel?, filters?, result, sourceMeta?, fetchedAt? }` |
| GET | `/api/market-insights/reports/:id` | **市场报告：读取当前账号的完整冻结快照** |

## 注意事项

- **不做"选品建议"结论。** 本模块只呈现事实（人工录入字段 + 可复算的报表指标），
  不产出"建议开发 / 不建议开发"这类评语 —— 骨架阶段没有可复算的确定性规则，
  凭空给结论就是被明令禁止的"硬编码成功状态掩盖未实现逻辑"。竞品分析的
  `buildFindings` 之所以能给结论，是因为每条都有 `evidence` 可复算，本模块尚无此基础。
- **数据来源必须逐项标注。** 对比表每行标注 `source`：`manual`（人工录入）或 `report`（我方报表）。
  人工录入的价格/评分是**用户填的**，不是平台抓的，界面不得暗示为平台数据。
- **未填字段一律 `null`，不补 0、不猜。** 与竞品分析「无数据的 ASIN 指标为 null 而不是 0」同口径，
  否则会把"没填"算成"表现差"。
- **关联不到我方报表指标的候选不参与指标均值与排名**，并在结果里明确标「无我方数据」
  （候选通常尚未上架，本来就不该有我方报表记录，这是正常状态而不是错误）。
- **无表头时只认第 1 列**（沿用 ASIN 清单的教训：猜错等于把无关数据写进字段）。
  第 1 列是 ASIN 就当 ASIN，否则当产品名称；第 2 列及以后**不猜不写**，
  预览界面如实显示"未识别到表头，只读取了第 1 列"。
- **超限一律报错、不截断**：单次导入 > 2000 行、对比 < 2 个或 > 10 个候选都返回 400 并说明原因。
- **同一账号 + 站点 + ASIN 不允许重复**（部分唯一索引 `WHERE deleted_at IS NULL AND asin IS NOT NULL`），
  应用层检查在并发下不可靠，冲突统一转 409。
- **软删语义**：`DELETE` 只置 `deleted_at`，因此"删除后重新添加同一 ASIN"是允许的。
- **区间锚点是数据最新日期而不是今天**：报表由人工导出、可能滞后数天，用今天会取到大半为空的区间。
- **日期一律按字符串处理**（`normalizeDateInput` / SQL `::text`），
  不要对 DATE 列回读值调用 `toISOString()`（东八区会整体前移一天）。
- **`attributes` 的键来自表头，值一律转字符串**。它是"数据源待定"的缓冲带：
  接入外部选品数据后，新字段可以先落这里，不必立刻改表结构。
- **对比快照冻结**：回看读的是当时落库的 `result`，不用今天的数据重算 ——
  否则同一份历史记录在不同日期打开会得到不同数字。
- **市场报告快照归属市场洞察模块**：产品开发页只负责展示和调用报告接口，不要把报告表写入候选池或对比表。
- **新模块的迁移号段必须先 grep 全局再定**（本次实际踩到）：本模块原定 300，实现期间发现
  **公告模块在并行开发中已占用 300/301**。迁移器以版本号为主键、`INSERT` 冲突即视为已应用，
  两模块同号时后跑的那个**被静默跳过**：表不建、接口全部 500，而迁移日志里没有任何报错。
  已改用 **400**。新增迁移前先 `grep -rn "version: " server/*.mjs`。
- **`express.raw` 的 `type` 必须排除 `application/json`**：粘贴文本走全局 `express.json`，
  文件上传走 `express.raw`，两者共用一个端点。若写成 `type: () => true`，raw 会连 JSON 请求
  一起吞掉，而此时 body 已被上游解析器消费，拿到的是空 Buffer —— 表现为"粘贴导入永远 0 行"，
  且没有任何报错。正确写法是 `type: (req) => !req.is('application/json')`。
- **固定路径必须注册在参数路由之前**：`/candidates/template` 与 `/candidates/import` 都要排在
  `/candidates/:id` 前面。Express 按注册顺序匹配，放后面时它们会被当成候选 ID，请求变成
  "候选 ID 无效"（ASIN 清单已经踩过同一个坑）。
- **过滤空行时不能丢掉原始行号**（本次实现中修掉）：先 `filter` 再按下标推算行号，
  表格中间每有一个空行，其后所有行号都会整体前移，而 `invalid` 里的行号正是给用户
  "回 Excel 里核对"用的 —— 指错行比不给行号更费时间。现在 1-based 原始行号在过滤前就绑在行上。

## 约束

- 必须复用：`readTableRowsFromBuffer`（编码回退与 XLSX 解析只有一处实现）、
  `summarizeAds` / `summarizeSales`（指标口径与 AI 助手同源）、
  `DataTable`、`TablePagination`、`ConfirmDialog`、`DatePicker`、项目主题 token
- 不得新增依赖（`read-excel-file` 已是既有依赖，经 `readTableRowsFromBuffer` 间接使用）
- 验证要求：
  - `pnpm run build`、`pnpm run lint`、`pnpm run test:server`
  - 新增单测覆盖：领域层校验/对比装配（纯函数）+ 导入解析层（列识别、四分类、行号、上限）——
    `server/product-dev.node-test.mjs`、`server/product-dev-table.node-test.mjs`，共 **50 项**
  - **接口与权限验收**：`API_PORT=8789 node server/index.mjs` 之后
    `API_BASE=http://localhost:8789 node server/product-dev-verify.mjs`（48 项，需要真实数据库）。
    注意端口要与**已加载本次代码**的实例一致 —— 验收时曾打到改造前启动的旧实例（8788）上，
    表现为**全部 404 且连未鉴权也返回 404**，很容易误判成路由没挂上
