# 责任田：市场洞察

## 功能描述

市场洞察负责把类目、产品、竞品、品牌与店铺信息整理成可保存、可比较、可追踪的市场分析结果，服务于选品判断和新品项目立项。

第一阶段不追求覆盖所有市场情报能力，先把现有市场调研和竞品分析能力组织成一个稳定入口，形成“发现市场 → 分析类目 → 研究产品 → 记录机会”的基础闭环。

本模块与相邻模块的对象和时机不同：

| 模块 | 主要对象 | 主要目的 |
| --- | --- | --- |
| 市场洞察 | 类目、节点、产品、竞品 | 了解市场结构并发现机会 |
| 竞品分析 | 用户输入的 ASIN | 即时比较少量产品 |
| 产品开发 | 候选新品 | 形成新品立项和开发过程 |
| ASIN 清单 | 已上架的自有 ASIN | 持续查看自有产品经营表现 |

## 功能清单

### 第一阶段：市场洞察基础版

- 产品地图：展示指定站点和节点下的重点产品、排名、价格、评分、评论量、品牌、BSR 和月销量估算。
- 类目概览：展示市场规模、商品数量、品牌数量、卖家数量、价格结构、集中度和新品结构。
- 市场透析报告：将一次类目调研结果保存为可回看的报告，保留来源、抓取时间、筛选条件和原始结果。
- 产品与竞品：复用现有竞品分析，补充父体与子体变体趋势和明细导出。
- 机会记录：允许将产品或市场分析结果关联到新品项目，避免分析结论停留在临时页面。

### 后续扩展

- 类目属性份额与趋势监控。
- 亚马逊节点的同类节点、错类节点、主投节点和备选节点分析。
- 类目级关键词、SERP、广告结构和获客成本分析。
- 自有 ASIN 矩阵和多节点榜单机会监控。
- 品牌产品矩阵、标杆竞品和竞品店铺分析。

## 入口与出口

- 当前入口：业务运营下的「市场洞察」（`/market-insights`），首期承载类目检索、市场分析和报告快照回看；顶部提供“类目洞察 / 报告记录”两个同级页面。
- 兼容入口：原「产品开发 → 市场调研」（`/product-dev/market`）继续保留，竞品分析跳转链路不变。
- 计划入口：随着真实数据能力完成，再在同一工作台内增加“产品地图 / 产品与竞品 / 机会记录”，不提前渲染未实现功能。
- 出口：市场报告可进入报告详情、竞品分析或新品项目；产品机会可关联到候选新品记录。
- 兼容要求：现有 `/product-dev/market`、`/competitor-analysis` 及其结果页保持可访问，新增入口不立即替换旧链接。

## API 明细

第一阶段已实现报告快照 API，市场调研仍复用产品开发和卖家精灵数据接口：

- `/api/product-dev/market/categories`：类目节点检索。
- `/api/product-dev/market/analyze`：类目市场结构分析。
- 竞品分析现有快照、公开产品、流量、评论和趋势接口。
- `server/sellersprite-public.mjs`、`server/sellersprite-blocks.mjs` 和 `server/sellersprite-config.mjs` 提供的采集、缓存和展示数据层。

已实现的报告接口：

- `GET /api/market-insights/reports`：查询当前账号的报告摘要，支持站点和数量筛选。
- `POST /api/market-insights/reports`：保存一次市场分析快照。
- `GET /api/market-insights/reports/:id`：查看当前账号的冻结报告结果。

前端入口已接入报告快照列表和保存动作，读取与写入均沿用当前账号隔离。

后续计划新增：

- `GET /api/market-insights/product-map`：读取指定站点、节点和时间点的产品地图数据。

报告快照接口已完成；产品地图接口、定时任务、通知和自动化抓取仍未实现。当前先保证手动触发、可追溯和可回看。

## 依赖关系

- 依赖：现有产品开发市场调研领域层、卖家精灵公开数据层、竞品分析数据层、`DataTable`、`TablePagination`、项目主题 token 和统一布局。
- 被依赖：后续新品项目、运营中心和机会监控会读取市场报告、产品地图和机会记录。
- 共享字段：`marketplace`、`nodeIdPath`、`asin`、抓取时间、数据来源、报告快照和关联候选产品。
- 数据隔离：报告和机会记录沿用当前账号隔离口径；不为管理员增加未经审计的跨用户查看入口。

## 影响范围

- 前端：新增 `src/features/market-insights/**` 和对应路由，复用现有竞品分析与产品开发组件，不复制基础表格和卡片组件。
- 服务端：新增市场报告领域层和路由；现有市场调研接口保持兼容。
- 数据库：第一阶段预计新增报告快照表，不修改现有产品开发候选表和竞品缓存表。
- 导航：新增一个业务运营一级入口，页面内部最多保留四个同级导航项，不在侧边栏继续增加深层菜单。
- 文档：本责任田与 `docs/superpowers/plans/` 下的开发计划是本模块的实现依据。

## 修改边界

- 可以改：`src/features/market-insights/**`、市场洞察路由、市场报告快照 API、相关责任田和开发计划。
- 谨慎改：`src/features/product-dev/**`、`src/features/competitor-analysis/**`、卖家精灵缓存和共享导航数据；改动前需要分别更新对应责任田。
- 绝对不能动：现有账号隔离、竞品分析历史快照的冻结语义、`amazon_*_daily` 写入逻辑、已有迁移版本号和第三方数据的来源标识。

## 注意事项

- 市场洞察页面不能把第三方估算利润显示成公司真实利润；没有成本、广告、物流和退货数据时，只能标记为“第三方估算”。
- 估算销量、估算份额和公开排名必须显示数据来源与抓取时间，不能伪装成平台官方数据。
- 报告保存后读取冻结快照，不用最新数据重算历史报告。
- 一个页面只承担一个主要决策问题：类目页回答“市场是否值得研究”，产品页回答“产品表现如何”，新品项目回答“是否进入开发流程”。
- 第一阶段不输出无法复算的“建议开发 / 不建议开发”结论；结论必须带数据依据或明确标记为人工判断。
- 不跨站点、跨币种直接汇总市场规模和销售额；不同站点分别展示。
- 未开发能力可以在开发计划中登记，但不能在页面中用假数据伪装成已完成能力。

## 约束

- 必须复用：现有 `DataTable`、`TablePagination`、统一 `Header/Main` 布局、卖家精灵公开数据缓存和竞品分析数据口径。
- 不新增第三方依赖；优先扩展已有领域层和数据解析器。
- 验证要求：涉及代码时执行 `pnpm run lint`、`pnpm run build` 和受影响模块测试；涉及真实卖家精灵调用时单独记录额度消耗和数据来源。
