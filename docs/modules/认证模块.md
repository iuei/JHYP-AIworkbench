# 责任田：认证模块

## 功能描述

负责内部登录、忘记密码、OTP 验证、认证布局和前端认证状态示例。

## 功能清单

- 登录页：提供公司内部账户登录入口。
- 忘记密码：保留密码找回表单，当前不从登录页暴露。
- OTP：保留一次性验证码输入和提交，当前不从登录页暴露。
- 认证状态：通过 Zustand 保存当前前端认证状态示例。
- 路由守卫：`_authenticated` 路由基于本地 mock 会话做前端访问拦截。

## 入口与出口

- 入口：`src/routes/(auth)/sign-in.tsx`、`forgot-password.tsx`、`otp.tsx`。
- 出口：认证成功后的跳转逻辑以现有实现为准，后续接入真实鉴权时需单独确认。

## API 明细

- 暂无完整真实 API。当前本地认证状态和表单仍以演示/前端状态为主，不代表真实服务端权限。

## 依赖关系

- 依赖：`src/features/auth/`、`src/stores/auth-store.ts`、`react-hook-form`、`zod`、`PasswordInput`、`InputOTP`。
- 被依赖：认证页路由、后续真实鉴权守卫、用户菜单退出逻辑。
- 共享字段：认证状态、用户会话信息、跳转目标。

## 影响范围

修改认证模块可能影响登录入口、找回密码流程、OTP 验证、全局认证状态和 `_authenticated` 访问控制。真实鉴权接入还会影响 API 错误处理、401/403 跳转和会话刷新策略。

登录页使用 `AuthLayout` 的 `split` 变体；忘记密码和 OTP 页面继续使用默认 `centered` 变体。登录页视觉调整不改变 API、JWT、权限、路由守卫或数据库。

## 修改边界

- 可以改：认证页 UI、表单校验、认证状态封装、演示提交逻辑。
- 绝对不能动：未确认前不得切换第三方认证服务、不得新增真实权限规则。

## 注意事项

- 当前认证守卫尚不完整，不要假设 `_authenticated` 已经具备真实权限保护。
- 当前 `_authenticated` 守卫只检查本地 mock token 和本地过期时间，用于无后端接口阶段的前端收口。
- 内部系统不开放自助注册，不保留注册页和注册入口。
- 密码输入统一使用 `PasswordInput`。
- OTP 输入使用现有 OTP 组件，不重复造输入框。
- 接入真实 API 前，应先确认登录、刷新、退出、401 处理和持久化方案。
- 登录页品牌区装饰图分别提供浅色与暗色资产。
- 小于 `lg` 时隐藏桌面品牌区，只保留移动端品牌锁定和登录表单。
- 内部系统不开放注册、社交登录或忘记密码入口。

## 约束

- 必须复用：`AuthLayout`、`PasswordInput`、shadcn/ui Form、Zod schema、`useAuthStore`。
- 验证要求：代码修改后运行 `pnpm run lint`、`pnpm run build`，表单行为修改需运行相关测试或手动验证。
