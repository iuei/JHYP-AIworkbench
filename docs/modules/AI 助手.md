# 责任田：AI 助手

> 需求基准：`需求文档.md`（v1.0）
> 本轮交付：**可信链路纵向切片（MVP-A）**，详见 `docs/superpowers/plans/2026-09-10-ai-agent-mvp.md`

## 功能描述

公司统一的 AI 与 Agent 入口模块，负责"员工提问 → 权限裁剪 → 工具取数/检索 → 模型生成结论 → 回答附出处与时效 → 全过程落审计"这一条可信链路的实现。

```
src/routes/_authenticated/ai-agent/
  route.tsx          # 员工面布局路由（模块内导航 + Outlet）
  index.tsx          # 对话工作台
  notes.tsx          # 我的知识沉淀（全员）
  knowledge.tsx      # 旧入口兼容跳转 → /knowledge（2026-09-18 起；2026-10-14 起默认子页即团队知识库）
  datasources.tsx    # 旧入口兼容跳转 → /admin/ai/datasources
  distill.tsx        # 旧入口兼容跳转 → /admin/ai/distill
  audit.tsx          # 旧入口兼容跳转 → /admin/ai/audit

src/features/ai-agent/
  types.ts           # 与 server 序列化字段一一对应的类型
  format.ts          # 日期/时间与来源文案格式化
  sse.ts             # SSE 客户端（fetch + ReadableStream，可 abort）
  api/queries.ts     # React Query hooks 与 mutations
  components/        # agent-nav / conversation-list / answer-card
                     # citation-panel / tool-trace-panel / document-dialogs
  pages/             # layout / chat-workbench / note-space / ai-admin-overview / admin-area-layout / ai-admin-layout
                     # knowledge-management / datasource-management / distill-management / ai-settings / audit-console
```

## 功能清单

- 对话工作台：两栏布局（会话列表 / 消息流），SSE 流式输出、停止生成、重新生成、轮次上限、空状态引导问题。页面按路由声明**铺满可用宽度**（`staticData.wide`）：默认的 `max-w-[1280px]` 居中会把中栏挤窄。
- **右栏已取消，依据移入回答卡片**（2026-09-15 按用户要求）：原先的三栏是「会话列表 / 消息流 / 本次回答的依据」，右栏（窄屏为抽屉）**已整体删除**；依据改由**每张回答卡片自己的「查看依据」按钮**按需展开（`answer-card.tsx`）。这样每条回答各自持有自己的依据，比"整个会话只能看最后一条"更准确；中栏消息流 `max-w-4xl` 居中且左右各留 `px-6`，因此宽屏下两侧是居中的留白（右栏不在时那一大片空白不再被一个面板占住）。
- **左栏宽度由用户自己定**（2026-09-14，2026-09-15 收敛为单栏）：左栏宽度不再写死在 class 里，用户可**拖拽分隔条**调整，分隔条聚焦后也可**键盘调整**（`←/→` 每次 16px、`Home/End` 到极限、**双击或 `Enter` 恢复默认**）；选择写入 cookie（`ai_chat_pane_widths`，180 天）下次进入仍生效，默认宽度与改造前一致（2xl 及以上 288，其余 256）。拖到极限时中栏保底 360px（`limitPaneWidths`，左栏隐藏时不占预算）；窗口变窄只收敛**显示**，不覆盖用户已保存的宽度。规则集中在 `pane-width.ts`（纯函数，可单测）。输入区**不再有**「页面宽度」按钮（2026-09-14 按用户要求移除，宽度调整入口只在分隔条上）。
- **聊天列表管理与删除会话（2026-09-18 补齐删除链路，2026-09-20 行操作改常显菜单）**：左栏支持新建会话、服务端搜索（防抖）、按「已置顶 / 今天 / 昨天 / 最近 7 天 / 最近 30 天 / 更早」分组、累积式「加载更早的会话」；每行的**重命名 / 置顶 / 删除收进常显的「⋯」菜单**（触发器 `aria-label="会话操作：<标题>"`，菜单项为「置顶会话 / 取消置顶」「重命名」「删除（destructive）」）。**「⋯」必须常显、不得依赖悬停**：改前是三个 `opacity-0 group-hover:opacity-100` 的图标按钮 —— 鼠标用户得先猜到"要悬停"，触屏设备（`hover: none` / `pointer: coarse`）**永远看不到**，等于找不到删除入口（实测：未悬停 `opacity: 0`，触屏下无任何机制把它变 1）。删除走 `ConfirmDialog` 二次确认，弹窗明确告知"该会话的全部问答与工具轨迹不可恢复，审计记录仍会保留"。**删除正在查看的那条会话时，中栏必须一起回到空态**：`ConversationList` 通过 `onDeleted` 把"删了哪一条"交回工作台（只有父组件知道当前选中的是哪一条），工作台仅在 `id === activeId` 时 `resetToNewConversation()`；此外工作台把「会话已不存在」（`GET /ai/conversations/:id/messages` 返回 404，含首页深链与旧书签指向已删会话）**在渲染期派生**为 `currentConversationId = null`，中栏因此回到新会话引导页而不是空白。**左栏的滚动容器不用 `ScrollArea`（2026-09-20）**：Radix 那层 `display: table` 包装会把内容恒定撑到 407px，左栏一收窄，「⋯」与「加载更早的会话」就被 `overflow-x: hidden` 裁断，改用原生 `overflow-y-auto overflow-x-hidden`（与中栏一致）。
- **使用边界提示只出现在空态**（2026-09-15）：三条说明（回答以知识库现有文档为准、非实时数据 / Enter 发送、Shift + Enter 换行 / 无权查询会被拦截并记录审计）从输入框下方的常驻行移到空态区，接在「AI 助手」标题与副标题下方**逐行展示**，对话一开始就随空态一起消失。理由：它们是"开口之前需要知道"的信息，常驻在输入区只是视觉噪音；与某次回答相关的数据来源与时效由回答卡片的声明条承担（那条必须保留）。若要再动这行文案的位置，注意别把声明责任也一起搬走——`answer-card.tsx` 的声明条与 `ensureFreshnessDeclaration` 的服务端兜底才是合规要求所在。
- **业务数据查询与分析**（M-A）：Amazon 广告/销售表现查询（含环比/同比、ACoS 涨跌驱动因子分解、异常阈值判定）、库存与订单查询；回答卡片渲染结构化表格（react-table）与趋势图/柱状图（recharts）。
- **产品主数据打通**（M-D 准备）：`product_master` 数据集建立 SKU ↔ ASIN/站点映射，使库存（按 SKU）与销售（按 ASIN）可以关联，可售天数与滞销判定改用完整销售历史。
- **主动分析**（M-B）：`scan_amazon_anomalies` 扫描全站 ASIN 输出异常清单与命中信号；`analyze_inventory_risk` 算可售天数并判定断货/积压/滞销与建议补货量；`query_amazon_performance` 不传 ASIN 时做全站聚合与 ASIN 排行。
- **我的 ASIN（2026-09-14 建立，2026-09-18 改为单集合）**：运营自建的**一份** ASIN 列表（`my_asin_items`，账号私有，**站点挂在每条 ASIN 上**；清单这一层已按用户要求取消）。页面 `/asin-watchlists`（侧边栏一级类目）支持单个添加、Excel 模板批量导入、表格 / 卡片两种读法、站点筛选与区间指标；AI 侧工具 **`query_my_asins`**（原 `query_asin_watchlist`，2026-09-18 改名并去掉清单参数）按站点分组对"用户指定的这一批 ASIN"取数（全站扫描做不到这一点），**不同站点货币不同，绝不给跨站点合计**。页面与工具共用 `asinSetPerformancePayload` / `myAsinMetricsPayload`，保证两处数字一致。详见 `docs/modules/ASIN 清单.md`。
- **竞品分析记录可被对话调取（2026-09-17）**：新增工具 **`query_competitor_analysis`**（`requiredRole: 'user'`），把「竞品分析 → 分析结果」里已落库的快照搬进对话 —— 三种调取方式（按记录号 `analysisId` / 按 `asin` 取包含它的最近一次 / 都不传则列出最近几次），**只读快照、不重新分析、不调用卖家精灵、零额度消耗**（卖家精灵按调用次数计费，对话顺手触发一次全维度分析会真实花钱，所以刻意**不提供任何"重新分析"参数**）。载荷层在 `competitor-history.mjs`，归属过滤沿用 `competitor-analysis.mjs` 的 `user_id` 判据（越权当不存在）。**一个必须记住的约束**：`orchestrator.mjs` 只把 `blocks` 压成 `viewSummary`（块的标题与行数）交给模型，**模型看不到块里的数据** —— 因此凡是要模型说出口的数字都必须进 `summary` / `rows`。详见 `docs/modules/竞品分析.md` 的「AI 对话里调取记录」一节。
- **提示词广场（2026-09-15）**：员工把自己反复输入的提问沉淀成模板（`ai_prompts`，**纯文本**，不带变量字段），页面 `/prompts`（**2026-09-16 阶段 C 起为一级路径**，此前在 `/ai-agent/prompts`；**默认子页为「共享提示词」，2026-10-14 起** —— 自己的条目走 `?view=mine`）支持新建 / 编辑 / 服务端搜索 / 提报共享 / 撤回 / 删除。对话内通过 **`@名称`**（或输入框旁的「提示词」按钮，两者走同一检测）调出面板：分组展示「共享提示词 / 我的提示词」、关键字搜索、`↑↓` 选择 / `Enter` 插入 / `Esc` 关闭；选中后把正文**填进输入框**（**不自动发送**，`@名称` 也**不上送服务端** —— 因此 `chat.mjs` 问答链路零改动）。**名称唯一分两层**：个人库内唯一 + 共享池内全局唯一（只做全局唯一会导致"任一人私有占名后他人再也建不了同名"，而 `@` 调用又必须无歧义）；提报共享 → 管理员在「经验审核」页审核 → 通过后全员可用。**与技能是并列实体、不合并**：技能仍是 `ai_skills` + SKILL.md、由设置中心维护，服务的是沉淀抽取的字段定义。
  - **AI 优化提示词（2026-09-15 追加）**：编辑弹窗正文框旁有常驻「优化提示词」按钮，由云模型把口语化草稿改写成结构清晰的提问模板。结果先以**「原文 / 优化后」对比**呈现，**点「采用」才替换正文** —— AI 改写有不确定性，一次点击就把用户刚写的内容顶掉是不可接受的事故；采用后仍可**一键撤销**（若又手动改了正文则撤销入口消失，免得把新改动一并吞掉）。采用只改输入框内容，**仍需点「保存 / 创建」才写库**。**只优化正文**：名称牵扯两层唯一性（交给模型只会凭空制造 409），说明 / 标签是给人看的元信息，都留给人写。**演示模式（未配置 API Key）下按钮禁用并说明原因**，服务端同样明确拒绝 400 —— 演示 provider 遇到这类提问只会回"我没有理解这个问题"，拿它当优化结果等于编造（失败不编造）。
  - **「标题」字段已下线（2026-09-15，按用户要求：只保留名称）**：一条提示词的名称与标题在列表里是上下两行、说的是同一件事，用户要填两遍还得自己造差别。**服务端保留 `ai_prompts.title` 列与历史值**（不删数据、不做结构变更），但接口不再返回、前端不再读写；`@` 面板的副行改显示「说明」（写的是"什么时候用"，比标题信息量更大）。编辑弹窗只剩：名称 / 提示词正文 / 说明 / 标签。
  - **展示方式：卡片网格为默认，卡片始终显示「创建人」与「使用次数」（2026-09-17，按用户要求"提示词广场使用卡片展示并显示使用次数以及创建人"）**：`pages/prompt-square.tsx` 把 `PromptLayout` 的默认由表格改回卡片（一条提示词要读的是名称 / 创建人 / 使用次数 / 正文四件事，卡片能一起摆开，表格把每条压成一行、完整正文要点「查看全文」）；**表格完整保留为可切换视图**（2026-09-16 的"内容优先用表格"并未作废，需要按状态 / 更新于 / 使用次数横向比对时用它）。卡片元信息行改为**始终**输出「创建人 `<登录名>` · 更新于 `<时间>` · 使用 N 次」——此前作者与次数是**条件渲染**，使用 0 次或无作者时整段消失，字段时有时无会让人误以为页面坏了，也分不清"这条没人用过"和"数字没渲染出来"；取不到作者写 `—`，**本人列表里创建人写「我」**（与表格「归属 / 共享人」列同一口径，不把 2026-09-16 已被否掉的一长串账号登录名请回来）。表格那一列表头随之由「调用」统一为「使用」，同一指标不在同一页面出现两种叫法。**偏好键换成 `prompt-square-layout:v2`**：旧键里可能存着"上一版默认（表格）之下的选择"，继续读旧键会让存过偏好的浏览器停在已废弃的默认上、看起来像改动没生效。**接口、服务端、`types.ts`、`queries.ts` 零改动**（`usageCount` / `ownerLogin` 早就在列表响应里）。
  - **完整正文改在弹窗里读，不再"展开拉长"（2026-09-17 同日第二轮，按用户要求"优化提示词广场的展开功能 点击卡片后以弹窗的方式呈现而不是拉长"）**：卡片与表格共用同一个**只读**详情弹窗 `PromptDetailDialog`（`components/prompt-dialogs.tsx`：名称 + 状态徽章 + 创建人 / 更新时间 / 使用次数 + 完整正文（固定高度内滚动）+ 标签 + 驳回原因，元信息与列表同口径 —— 本人条目写「我」）。**卡片整卡可点**（`role='button'` + `tabIndex` + `Enter/Space`，与数据源卡片同一形态，鼠标与键盘两条路都在），表格操作列则是「查看全文」按钮；两条路径都走同一个 `openDetail`，行为不可能漂移。**两道必须的防御**：操作区容器 `onClick` 里 `stopPropagation()`（否则点「删除」会顺带弹详情），按键处理器里 `event.target !== event.currentTarget` 直接返回（焦点在内部按钮上按 Enter 时 keydown 同样冒泡上来）。**原来的两种"展开"都已删除**：卡片的 `sm:col-span-2 2xl:col-span-3` 跨列拉长、表格的"行下方插一行"（连 `Fragment` 导入一起清理）。**只读**：提报 / 编辑 / 撤回 / 删除仍只在卡片与表格行上 —— 它们各有确认与状态流转，塞进详情浮层里最容易误点。**接口、服务端、`types.ts`、`queries.ts` 仍然零改动**。
  - **提示词广场有自己的顶部子页（2026-09-15，按用户要求"提示词广场没有顶部子页面"）**：顶栏**不再挂 AI 助手模块导航**（对话 / 我的 ASIN / 我的沉淀），改为它自己的两个子页 **「共享提示词 ｜ 我的提示词」**（`components/prompt-square-nav.tsx`，与 `admin-ai-nav.tsx` 同构）。两个子页**共用同一路由**、用 search 参数 `view` 表达（`?view=mine`；**默认页 = 共享提示词（2026-10-14 改，此前默认是我的）**，URL 干净、侧边栏链接与它天然一致）—— 拆成两个路由要动路由树，而它们只是同一份列表的两种取数范围。页面按 `view` **只渲染当前子页**（原先两块纵向堆叠，用户要一路下滚才看到"同事共享"那块），并按子页 `enabled` 只拉那一份数据；搜索词在子页间保留。同时给该路由声明 `staticData: { title: '提示词广场' }`：子页默认继承模块级标题「AI 助手」，而它已是侧边栏一级类目、顶栏又是自己的子页导航，标题再写「AI 助手」就自相矛盾。**取舍**：这一页不再有一键跳去对话/沉淀的入口，走侧边栏即可 —— 一级类目本就不该挂在别人的二级导航下。
- **数据源与导入**（管理员）：4 个数据集的 CSV 导入（模板下载、列名校验、整批拒绝、覆盖/追加）、导入记录与失败行明细、数据集覆盖率与数据时效展示。
- AI 回答卡片：固定顺序为结论 → 支撑数据 → 声明条（数据来源 / 数据截至 / 权限范围）→ 反馈行（**查看依据** / 有用 / 有问题 / 重新生成）。**卡片内不直接渲染引用清单**：点「查看依据」才在卡片底部展开引用文档与「工具调用与参数」（默认收起，箭头旋转表示开合）。既无引用文档又无工具调用时**不给按钮**（点开空面板比没有入口更糟）。
- **回答格式统一（2026-09-15）**：正文排版由**服务端规范 + 前端渲染层**两端共同定义 —— 首段固定 `## 结论`，后续小标题只能从「关键数据 / 执行步骤 / 说明 / 注意事项」里选，正文禁止 Markdown 表格与代码块（结构化数据已由卡片内的 `blocks` 渲染）。真实模型一直在输出 Markdown，而此前正文按纯文本渲染，用户看到的是 `## 结论`、`**20.17%**`、`| 驱动因子 |` 这些**源码符号**。改一端必须同步改另一端，详见「注意事项」。
- 过程可见：流式期间展示编排进展（`正在检索知识库… ✓ 已检索 xx 篇文档`）。
- 知识库管理（管理员）：文档列表、文本/Markdown 上传、有效期、下线、重新启用、删除、手动重建索引。

- 审计台（管理员）：会话轨迹、工具调用明细、拦截记录、管理动作日志、CSV 导出。
- 工具调用：本轮实现 `search_knowledge`（user）、`rebuild_knowledge_index`（admin）、`deactivate_document`（admin）。

  - 员工侧「我的沉淀」（`/ai-agent/notes`）：手工新建、会话内「沉淀为知识」由 AI 整理、编辑、提交审核、归档、删除、导出（CSV / 合并 Markdown / JSON），并配置「知识沉淀」技能（**默认关闭**、触发方式、每日 AI 整理次数上限、要整理的字段）。
  - 管理员侧「沉淀管理」（`/ai-agent/distill`）：全部账号的沉淀列表与按账号统计、审核队列（通过 → 生成 `source_type='experience'` 文档并标注提报人；驳回必须填原因）、编辑、归档、软删、按筛选导出、技能全局启停与账号启用一览。
  - **写权分离**：员工只能把沉淀置为「待审核」，只有管理员能 `published` / `rejected`，管理员也不能把他人私有草稿直接改成已发布。
  - **未审内容不进检索**：私有沉淀只存在于 `ai_knowledge_notes`，不生成 `ai_documents`，因此不可能被问答检索到；管理员在对话检索中同样看不到他人私有沉淀。
  - **不编造**：AI 整理失败（模型不可用 / 输出无法解析）时降级为「原文草稿」（`degraded=true`、字段留空、原文放 evidence），界面明确提示字段待补充。
  - `provenance`（本人所写 / 模型推断）与 `evidence`（原文引句）用于让审核人一眼判断可信度。
  - **加固（2026-09-11）**：员工接口收窄为**所有者视角**（管理员也不能借员工接口读写他人条目，一律 404）；`provenance` 与 `evidence` 一律由**服务端**推导与逐字核对；审核通过改为**行锁 + 单事务**（文档生成失败保持待审核、可重试、幂等唯一约束兜底）；已发布条目同标题再沉淀生成**新修订**（重新审核，旧公共文档不被覆盖）；员工不能改待审核内容（409）；管理员时间筛选与导出共用同一组参数；每日配额改为**并发安全的预占**。详见 `docs/superpowers/plans/2026-09-11-knowledge-distill-hardening.md`。
- **信息架构：使用面与治理面分离（2026-09-11 重构）**：
  - 员工面（`/ai-agent`）：模块内导航为「对话」「我的 ASIN」「我的沉淀」**三项**（**「提示词广场」已于 2026-09-15 按用户要求移除** —— 它在侧边栏是一级类目、页面顶栏又是它自己的两个子页，再挂在这里等于把一级类目降格成 AI 助手的子页，同一个入口还会在一屏里出现两遍），**注入全局 Header 中段**（`HeaderSlot`）；

## 入口与出口

- 入口：员工面为侧边栏一级类目 **AI 助手** → 对话（另有并列的 **知识库**（团队（默认）/ 个人）与 **我的 ASIN**、**提示词广场**一级类目）；治理面为侧边栏一级类目 **系统管理** → **AI 治理**（仅管理员），进入后直接落在「数据源与导入」（`/admin/ai` 重定向，2026-09-16 起不再有概览首页、2026-09-18 起落点由知识库改为数据源与导入），再由页内顶部导航横向切换四个子页。治理页的路由在 `/_authenticated/admin/ai/*`，由 `admin/route.tsx` 统一做 `beforeLoad` 管理员守卫。
- **URL 参数（2026-09-15 新增，均可选）**：`/ai-agent?conversationId=<id>` 进入即选中该会话（首页「最近对话」深链，语义与左栏 `onSelect` 一致：设 `activeId` 并清空流式状态，消息由 `activeId` 自动驱动）；`?focus=composer` 进场即聚焦输入框（首页「问 AI」深链）。解析器在 `src/features/ai-agent/search-params.ts`，只作用于 `/ai-agent` 本身（不影响 notes / asin-watchlists 等子路由），脏值忽略——落不到具体会话时就是普通新对话入口。
- 出口：问答结果留在会话内；知识库/审计操作为原地刷新；被拦截请求统一返回「当前账号无权查询该数据，请联系管理员。」

- `POST /api/ai/messages/:id/feedback` - 有用 / 有问题 / 纠错反馈。

- `GET /api/ai/knowledge/documents` - 文档列表（管理员）。
- `GET /api/ai/knowledge/documents/:id/chunks` - 切片预览（管理员）。
- `GET /api/ai/knowledge/public/documents?page=&pageSize=&sourceType=&keyword=` - **团队知识库列表（员工面，2026-09-18 新增）**：只回 `status='active'` 的文档（**服务端强制，不接受请求参数覆盖**），只暴露对外字段（id / 标题 / 来源 / 版本 / 分类 / 有效期 / 切片数 / 提报人 / 更新时间），**不含 `correctionCount` 这类治理口径**。权限只要求登录（无 `adminGuard`）。
- `GET /api/ai/knowledge/public/documents/:id/chunks` - **团队知识库正文切片（员工面，2026-09-18 新增）**：先校验文档存在且 `status='active'`，**已下线一律 404**（下线的语义就是"不再被引用"，不能继续暴露正文）。
- `POST /api/ai/knowledge/documents` - 粘贴文本入库（管理员）。
- `POST /api/ai/knowledge/documents/upload` - 文件上传入库（管理员）。原始 body + `X-File-Name` 头（`encodeURIComponent`），一期支持 TXT / Markdown / CSV / JSON。

- `DELETE /api/ai/knowledge/documents/:id` - 删除文档及其切片（管理员）。
- `POST /api/ai/knowledge/documents/batch` - **批量下线 / 启用 / 删除**（管理员）。body `{ action: 'offline'|'online'|'delete', ids: number[] }`，单批上限 200、重复与非法 id 自动剔除；响应 `{ action, requested, succeeded, failed, results[] }` 固定 200 —— **逐条执行既有领域函数并逐条写审计**（`detail.via='batch'`），部分失败由 `results[].message` 表达（如「文档不存在或已下线」）。
- `POST /api/ai/knowledge/reindex` - 重建知识索引（管理员）。
- `GET /api/ai/knowledge/feedback` - 待处理纠错反馈（管理员）。
- `POST /api/ai/knowledge/feedback/:id/handled` - 标记反馈已处理（管理员）。
- `GET /api/ai/datasets/freshness` - 各数据集最新导入时间（管理员）。
- `GET /api/ai/datasets` - 数据集清单：行数、覆盖周期、最近导入状态（管理员）。**不含行数据**：行详情是管理员点开卡片才拉的。
- `GET /api/ai/datasets/rows?dataset=&page=&pageSize=&keyword=` - **数据集行详情**（管理员）：返回 `dataset / label / columns / rows / total / page / pageSize`。列名走数据集规格白名单（模板列 + 附加列，如库存快照的 `snapshot_at`），关键词只搜文本类列（`asin` / `campaign` / `sku` / `marketplace` / 日期列）；未知数据集 400。
- `GET /api/ai/datasets/rows/export?dataset=&keyword=` - 行数据 CSV 导出（管理员，与列表同一筛选条件）：表头为中文列名、带 BOM；**导出动作写审计**（`action='dataset_export'`，detail 含 dataset / keyword / rows / total / truncated）；超过 2 万行时返回 `X-Export-Truncated: true`。
- `GET /api/ai/imports/template?dataset=` - 下载导入模板 CSV（管理员）。
- `POST /api/ai/imports?dataset=&mode=&onRowError=` - 上传导入（原始 body + `X-File-Name` 头）（管理员）。
- `GET /api/ai/imports?dataset=&page=&pageSize=` - 导入记录（含失败原因），返回 `imports / total / page / pageSize`（管理员）。
- `GET /api/ai/audit/conversations?page=&pageSize=` - 会话轨迹（返回 `total / page / pageSize`）。
- `GET /api/ai/audit/conversations/:id/trace` - 完整轨迹（审计完整性回溯）。
- `GET /api/ai/audit/runs?page=&pageSize=` - 工具调用明细（返回 `runs / total / blockedTotal / page / pageSize`；`blockedTotal` 按**同一组筛选条件**统计，供指标卡使用）。
- `GET /api/ai/audit/logs?action=&actions=a,b&page=&pageSize=` - 管理动作日志（同样返回 `total / blockedTotal`）；`actions` 支持多动作合并筛选（拦截记录页用 `tool_blocked,forbidden`）。
- `GET /api/ai/audit/export?type=runs|logs|conversations` - CSV 导出（导出动作本身写审计）。
- `GET /api/ai/usage` - token 用量统计（按天聚合）。
- `GET/PATCH /api/ai/settings` - 模型与编排配置（管理员）。PATCH 额外支持 `modelBaseUrl`、`forceDemo`、`modelApiKey`（`null`/空串表示清除密钥），以及卖家精灵 MCP 的 `mcpEnabled` / `mcpEndpoint` / `mcpPrefix` / `mcpTimeoutMs` / `mcpSecret`（同为 `null`/空串清除）。
- `POST /api/ai/settings/test` - 测试模型连通性（管理员）。可带未保存的候选参数先测后存；只做一次极短补全调用，不落库。
- `POST /api/ai/settings/mcp/test` - **测试卖家精灵 MCP 连通性**（管理员）。可带未保存的 `mcpSecret` / `mcpEndpoint` 先测后存；返回 `{ ok, message, kind?, endpoint?, toolCount?, latencyMs?, remoteTools[] }`。**密钥无效时 `ok=false` 且 `kind='auth'`** —— 卖家精灵不以 HTTP 错误表达鉴权失败（见注意事项）。
- `POST /api/ai/settings/mcp/sync` - **同步卖家精灵工具清单到 `ai_tools`**（管理员）。用**已保存**的配置拉 `tools/list` 并入库（新工具 `enabled=true` / `required_role='user'`，已存在的只更新描述与 schema、**不动开关**，远端已下线的连同本地记录删除），写审计（`detail.mcpSync`）。**只有入库的工具才会被注册给模型** —— 同步后「工具开关 / 角色裁剪 / 未注册拒绝」这些既有机制对它们自动生效。
- `PATCH /api/ai/tools/:name` - 工具启用/停用（管理员，内置与 MCP 工具同一接口；工具名上限 120，与 `ai_tools.name` 列宽一致）。

### 知识沉淀的状态码语义（不要混用）

| 状态码 | 含义 | 典型场景 |
| --- | --- | --- |
| 400 | 输入不合法 / 状态流转本身不允许 | 驳回未填原因、`pending→pending` 重复提交、原文依据不在会话中、时间范围非法 |
| 404 | 条目不存在**或无权操作（不泄露存在性）** | 员工接口访问他人条目；管理员走员工接口访问他人条目 |
| 409 | 状态冲突（当前状态不允许该操作，可刷新后重试） | 编辑待审核/已发布条目、审核非待审核条目、同标题条目正在审核中 |
| 429 | 当日 AI 整理配额已用尽 | 并发触发 AI 整理超出上限 |

## 注意事项

- **卖家精灵 MCP 的"假成功 / 假失败"形态（2026-09-16，全部实测，两次都踩到了）**：接入外部 MCP 最容易踩的不是网络，而是**服务端不用错误表达错误状态**。
  1. **工具清单里始终混着 `secret_*` 状态占位条目** —— 这是本模块**最严重的一次误判事故**。实测：有效密钥返回 **49 条 = 45 个真实工具 + `secret_invalid` + `secret_expired` + `secret_unauthorized` + `secret_no_remaining`**；密钥无效时**才**只返回 `secret_invalid` 一条。早期实现写的是"清单里出现 `secret_invalid` 就判密钥无效"，于是**密钥完全有效的用户一直看到"密钥不合法"**（用户已开通套餐，命令行用同一把密钥实测能拉到 45 个工具）。
     **正确判据只有一个：真实业务工具数为 0** —— `mcpListTools` 先按 `secret_` 前缀摘掉占位条目，再判剩余数量；为 0 时用占位条目名给出**具体原因**（过期 / 未授权 / 次数用完）。占位条目还要在 `normalizeMcpTool` 里再拦一道：它们的描述就是"密钥不合法"这类状态文本，注册给模型只会让模型去调一个必然失败的工具。
     **教训**：第三方的"状态占位"往往**与真实状态无关地常驻**，不要用"出现了某个名字"推断状态，要用"**真实数据条数**"。
  2. **失败被包成"正常数据"**：`{"content":[{"type":"text","text":"{\"code\":\"ERROR_UNAUTHORIZED\",\"message\":\"未授权\"}"}],"isError":false}` —— `isError` 是 **false**。鉴权类由客户端层 `detectAuthFailure()` 升级为 `auth` 错误（判定刻意收紧到**短文本 + 结构化错误码**，宁可漏判也不误伤评论正文里的"未授权"字样）；**其它** `ERROR_*` 业务错误由结果整形层的 `detectErrorEnvelope()` 兜住。两处都不能省：不拦下来，模型会把错误码当查询结果继续分析。
  3. **不带密钥调用工具**返回 Java 内部异常文本且 `isError:true`（走通用 server 错误分支即可）。
  4. **单条记录形态容易被当成"空结果"**：产品类工具（`asin_detail` / `keepa_info`）返回的是 `{code:'OK', message:'成功', data:{…}}` —— **`data` 是对象而不是数组**。早期 `shapeMcpToolResult` 只认数组，于是这类结果被标成 `empty: true`、`blocks: []`，模型只能读到一段被截断的 JSON 文本。现在单条记录同样进 `rows`（字段完整回灌模型），但**不生成表格块**（一条记录几十个字段，横排表格在页面上读不下去）。
- **管理员很容易把密钥填进端点框**：官方文档给了 `https://mcp.sellersprite.com/mcp?secret-key=xxx` 的"URL 直连"写法，整条粘进去**也能连通**，但密钥会**明文**留在 `mcp_endpoint` 列（不进加密列、审计与导出里都会出现），而界面显示"密钥来源：未配置"。前端保存/测试前会把它搬到密钥框并提示，服务端 `splitEndpointSecret()` 在 PATCH 时再兜一次（只摘 `secret-key`，其它查询参数保留），审计里记 `mcpSecretMovedFromEndpoint`。
- **MCP 请求头的两个硬要求**：`Accept` 必须**同时**含 `application/json` 与 `text/event-stream`（缺任一部分直接 400，而 Node `fetch` 默认是 `*/*`），鉴权头名固定 `secret-key`（不是 `Authorization: Bearer`）；端点是 Streamable HTTP（**必须 POST、路径精确到 `/mcp`，带结尾斜杠 404**，没有 SSE 长连接），服务端无状态、无 `mcp-session-id`。实测向它发未实现的方法会吐回**完整 Java 堆栈**（数 MB），`mcpRequest` 因此加了 4MB 响应体上限。
- **MCP 工具名会一路写进审计，列宽必须一起放宽**：本地工具名是 `<前缀>__<远端工具名>`，迁移 117 把 `ai_tools.name`（80 → 120）与 `ai_runs.tool_name`、`ai_audit_logs.target_id`（80 → 120）一起放宽 —— 只放宽 `ai_tools` 的话，任何超过 80 字符的工具名**一被调用**就会在写审计时 `value too long`，表现成整轮对话直接失败；`PATCH /ai/tools/:name` 的长度上限也必须同步（否则点开关会作用到被截断的另一个名字上）。
- **MCP 工具的参数 schema 必须归一化后再用**：MCP 允许 `type: ["string","null"]`、`$ref`、`oneOf` 等 `validateParams` 不认识的写法，原样透传会让**合法的模型调用被判成"参数非法"**。`normalizeMcpSchema` 只保留支持的关键字并递归处理嵌套，拿不准时**宁可少校验**。
- **密钥无效与"未配置"是两件事**：密文解不开（换过 `AI_SETTINGS_SECRET`）标记 `mcpSecretInvalid` 并提示重填，而不是当成未配置 —— 否则界面显示"未配置"，运维会去填一把已经存在的密钥。
- **额度按 HTTP 请求计数**（卖家精灵一次 `tools/call` 记一次，月付档普遍 40 次/分钟），且 42 个工具全量注册会明显占用模型上下文。因此工具同步后可在「工具开关」里逐个停用，页面也明确提示"只启用常用的"。
- **注意第三方条款**：卖家精灵《密钥使用规范》写明 MCP 授权「个人使用」、限制同一密钥被多主体/多客户端共享，超出场景官方指引改用 API 服务。这一条写在配置卡底部，属于**必须让使用者自己知情**的约束，不要因为"看起来啰嗦"而删掉。
- **对话输入行的控件必须统一 44px 高（2026-09-15）**：文本域是 `min-h-[44px]`，整行又是 `items-end` 底对齐 —— 任何控件比它矮都会"陷进去一截"（实测按钮 36px vs 文本域 44px，用户就是这么看出"三个按钮高度不一致"的），同排按钮之间高矮不一也会显得零散。图标按钮用 `size-11`、文字按钮用 `h-11`；44px 同时是 WCAG 2.5.8 触控目标尺寸的下限。**改这一行时整行一起量**，且宽屏与窄屏各量一次（窄屏多一个 `lg:hidden` 的「打开会话列表」按钮，它不在宽屏的可见集合里）。
- **数据源行详情：列名只能来自数据集规格（2026-09-15）**：`listDatasetRows` 会把列名拼进 SQL（列名不能参数化），因此新增展示列必须走 `datasetRowColumns()` / `spec.columns`，**不要**在路由里接收前端传来的列名或排序字段。行详情与清单接口刻意分开：清单是进页面就要的轻量统计，行数据是管理员点开卡片才拉——把行数据塞进 `/datasets` 会让首屏为一份没人看的数据买单（前端用 `enabled` + `placeholderData` 保证关闭弹窗时不发请求、翻页时不塌陷）。
- **会话列表的"管理"动作必须把中栏状态一起考虑（2026-09-18）**：删除会话、以及任何让 `activeId` 指向一条**不存在会话**的路径，都不能只改左栏。`GET /ai/conversations/:id/messages` 对已删除或不属于本账号的会话一律返回 404，而中栏**没有错误分支** —— 只把左栏条目拿掉，用户看到的是"没有内容也没有引导"的一整片空白，只能手动点「新建会话」。两条路径都要守：
  1. 删除成功由 `ConversationList` 的 `onDeleted` 回调通知工作台，**且只在删掉的正是当前选中会话时才重置** —— 删别的会话跟着清空，等于"删了一条却把用户正在看的对话一起弄丢"；回调里要用 `pendingDelete` 的**快照**而不是 state（请求在途中 `onSettled` 已把它清空，回调再读会拿到 `null`）。
  2. 会话 404 用**渲染期派生**（`conversationMissing` → `currentConversationId = null`）兜底，**不要写成 `useEffect` 里 setState**：`react-hooks/set-state-in-effect` 会直接报错，而且"服务端说这条会话没有"每次渲染都算得出来，不需要多一份 state 与一轮级联渲染。渲染与 `send` 都必须用派生出来的 `currentConversationId`，否则用户在空态下提问会被发往那条已不存在的会话。
  3. **React Query 在 refetch 失败时会保留上一次成功的数据**（只把 error 挂上去），所以 `persisted` 也要在 `conversationMissing` 时清空，否则会出现"服务端说会话没了、界面还挂着它的旧消息"。`useDeleteConversation` 删除成功后顺手 `removeQueries` 掉该会话的消息缓存。
- **行内操作入口不允许"悬停才出现"（2026-09-20，实测踩到）**：`opacity-0 group-hover:opacity-100` 这类写法把**唯一入口**藏进 hover —— 触屏设备（`hover: none`）下它**永远不显形**，用户根本找不到（用户报障原话就是"如何才能删除"）。规则：
  1. 需要 hover 时只能把它当**增强**（默认可见 → 悬停改样式/提高对比度），不能当入口的显示条件；确需按设备区分的，用 `pointer-coarse:` / `pointer-fine:` 变体，别用 hover 作为唯一开关。
  2. 成熟形态是**常显的「⋯」菜单**（`DropdownMenu` + `DropdownMenuTrigger`，触发器给 `aria-label` 带上业务主语如「会话操作：<标题>」，好让屏幕阅读器区分多行）。
  3. **Radix DropdownMenu 在 Radix Sheet(Dialog) 内可正常工作**（菜单 Portal 到 `body`）：窄屏抽屉里整套"打开菜单 → 删除 → 确认"实测通过。但写测试时记住**菜单项不在行内**，要在 `page` 级查找（`page.getByRole('menuitem', …)`），用行作为 scope 会找不到。
  4. 测试选择器：会话标题按钮的可访问名是「<标题>N 条消息」，而「⋯」触发器是「会话操作：<标题>」，两者都含标题 —— 用 `/标题/` 会 strict mode 冲突，必须锚定 `/^标题/`。窄屏用例同理：桌面左栏仍在 DOM 里（`hidden lg:flex`），同名的搜索框与 `li` 各有两个，取 `.last()`（抽屉在 DOM 靠后）才是可见的那个。
- **左栏滚动容器：不能用 `ScrollArea`（2026-09-20，用户报障「缩减宽度时⋯的更多按钮会被遮挡截断，加载更早的会话按钮也是一样」）**：与中栏消息流是**同一个** Radix 陷阱 —— Viewport 内层被插入 `display: table; min-width: 100%` 的包装（内联样式，class 覆盖不掉），table 按内容 **min-content** 撑宽而不跟随容器。实测左栏 200 / 240 / 288 三档下该层恒为 **407px**：行右端的「⋯」按钮 `right=611`（左栏右边界 420）、「加载更早的会话」按钮 `right=619`，落到栏外被 Viewport 的 `overflow-x: hidden` 裁掉。**修法**：左栏改用原生 `div.overflow-y-auto.overflow-x-hidden` + 内层 `pe-2`（长标题由 `truncate` 自己收），与 `chat-workbench.tsx` 中栏一致。**验证方式（重要）**：`conversation-list-layout.test.tsx` **必须 `import '@/styles/index.css'`** —— 不导入全局样式时 Tailwind 类全是空类，怎么量都不复现溢出（踩过：先写的一版测试在修复前"通过"了，等于假保护）；断言也不能用同步快照，全量并行跑时会量到中间帧，必须 `vi.waitFor` 轮询。修复后实测：`scrollWidth == clientWidth`、行宽 176/216/264 跟随栏宽、「⋯」在栏内 32px。
- **对话页消息流不要包回 `ScrollArea`（2026-09-15）**：Radix `ScrollArea` 的 Viewport 内层固定插一个 `display:table; min-width:100%` 的包装（内联样式，class 覆盖不掉），table 布局按内容 min-content 撑宽 —— 一段含长 URL / 长 JSON 的回答就能把窄中栏的内容区撑到上千像素并被 `overflow-x: hidden` 硬切。中栏必须用原生 block 滚动容器（`overflow-y-auto overflow-x-hidden`）。同理，**任何"可能包含不可断行长串"的文本容器都要 `wrap-anywhere`（`overflow-wrap: anywhere`），不要用 `break-words`** —— `break-word` 不参与 min-content 计算，撑宽依旧发生。宽表格交给自身 `overflow-x-auto`：只有当容器宽度不被内容撑开时，它才真的会滚动。
- **分页后指标卡必须用服务端计数（2026-09-14）**：列表改为服务端分页后，**不能**再对当前页数据做 `filter().length` 当指标——那会变成"本页被拦截数"，翻页数字还会跟着变。`/audit/runs`、`/audit/logs` 因此返回 `total` 与 `blockedTotal`（与列表同一组筛选条件，改列表筛选时必须同步改计数 SQL，否则页数与总数会对不上）。计数类查询一律走 `pageSize=1` + `total`，不把整页日志拉下来数个数（原概览页的拦截信号就是这么算的；该页已于 2026-09-16 移除，原则不变）。
- **多选只在"当前筛选 + 当前页"内有效（2026-09-14）**：知识库与经验审核的多选集合绑定在 `selectionKey`（筛选 + 页码）上，键一变选择自动视为空。**不要改回 `useEffect` 清空**：一是 effect 里 setState 会多一次级联渲染且存在"选中项仍属于上一页"的中间帧，二是翻页保留选择会让批量删除作用于当前已看不见的行。批量操作按钮的可用性由 `canDeleteNote` / `canArchiveNote` 派生，部分失败必须逐条展示原因（服务端逐条返回 `results[].message`）。
- **批量接口不接受"整批失败"以外的静默**：批量动作固定返回 200，用 `succeeded` / `failed` / `results[]` 表达结果，且**每一条都写审计**（`detail.via='batch'`）——审计台必须仍能回答"这一篇是谁在什么时候下线/删除的"，不能只留一行"批量操作 30 条"。
- **汇总口径：广告销售额与业务销售额必须分开（2026-09-14 修复）**：`summarizeAds` 与 `summarizeSales` **都返回 `sales`**，合并时必须走 `mergeAdAndBusinessSummary()` —— 它保证 `sales` = 广告销售额、`businessSales` = 业务销售额。直接写 `{ ...ads, ...sales }` 会让业务销售额覆盖广告销售额，而 ACoS、卡片标签与事实清单都是**广告口径**，于是出现「广告销售额 60000、ACoS 25%」这种自相矛盾的组合（同一份数据真实 ACoS 是 8.3%），且编排层禁止模型改数字，错误会原样进结论。单测里两个口径的数字**不要取相等值**（原测试恰好相等，掩盖了这个缺陷一年多）。
- **`period.days` 是区间天数，不是行数**：行数在 `period.rowCount`。`summarizeAds().days` 统计的是参与汇总的**行数**（单 ASIN 30 天 × 5 campaign = 150），当作"区间天数"会写出「统计区间 …（150 天）」。
- **DATE 列按字符串处理**：`server/db.mjs` 用 `pg.types.setTypeParser(1082, v => v)` 覆盖了 pg 默认行为——默认会把 DATE 解析成**本地时区午夜**的 Date，再经 `toISOString()` 整体前移一天（东八区必现）。踩过的后果：按区间过滤时丢掉第一天（30 天窗口只算 29 天）、日均销量窗口偏移、提示词里出现 `覆盖 Fri Sep 11 ~ Wed Sep 10` 这种反向区间。新增涉及 DATE 列的查询时直接按 `'YYYY-MM-DD'` 字符串处理。
- **角色映射**：需求文档写 `user`/`admin`，现有库实际是 `operator`/`admin`。工具契约里 `requiredRole: 'user'` 表示"任意启用账号"，`'admin'` 表示"必须 `role = admin` 且启用"。不改 users 表。
- **迁移版本冲突坑**：`schema_migrations.version = 1` 曾被快捷导航占用（该模块已于 2026-09-15 删除、记录已清理），AI 迁移仍从 **100** 起编号——**号段保持不变**，因为库里已有 100–116 的已应用记录，改成从 1 开始会与既有记录错位。新增迁移一律取当前最大号 +1，别复用空出来的小号段。
- **中文全文检索**：库内无 `zhparser`，中文分词不可用。检索采用「关键词（CJK 双字切分 + 拉丁词）+ `pg_trgm` 相似度 + `simple` 全文」混合打分，勿直接依赖 `to_tsquery` 处理中文。

- **沉淀权限口径：可见 ≠ 可操作（本轮加固）**：`permissions.mjs` 里三个判定不能混用——
  `canSeeNote`（本人或管理员，**只给管理视图的展示用**）、`canOwnNote`（仅所有者，**员工接口 `/api/ai/notes/*` 专用**）、`canManageNote`（仅启用管理员，`/api/ai/distill/*` 专用）。
  员工接口一律 `getOwnedNote` + `scope='self'`，管理员通过员工接口访问他人条目按不存在返回 404（不能让管理员借员工接口绕过管理动作的审计口径）；`assertOwnerAction` 是第二道保险，防止后续把查询换成管理视图后静默放开越权写。
- **provenance 与 evidence 一律服务端定（本轮加固）**：
  - `provenance` 由 `deriveProvenance(sourceKind)` 推导（会话来源 → `inferred`，手工 → `user_stated`），**请求体里的 provenance 只做枚举校验、不落库**（客户端能改判就等于可信度标注失去意义）；合并时"只降不升"（一旦有模型推断内容并进来就整体标为推断）。
  - `evidence` 用 `isEvidenceFromConversation` 逐字核对（只做换行统一、逐行去空白、脱成对引号三类无损规整，**禁止用相似度代替逐字验证**）：抽取草稿核对不过就置空并标 `evidenceRejected`（界面提示"原文依据待补充"，但不谎报 `degraded`）；会话来源条目在**保存/修改**时核对不过直接 400，不静默清空。
- **审核通过是"行锁 + 单事务"（本轮加固）**：`reviewNote` 在同一事务里完成「`SELECT … FOR UPDATE` 锁行 → 校验仍为 pending → 生成/复用公共文档 → 更新状态与 `published_document_id` → 写审计」，任一步失败整体回滚（条目保持 pending 可重试，不会出现"已发布但没有文档"）；重复/并发审核返回 **409**。`ingestDocument` 支持传入外部事务 client（`client` 参数），不要再在路由里拼第二套文档写入逻辑。
- **同标题再沉淀 = 新修订（本轮加固）**：同标题条目已是 `published` 时**不原地合并**（否则公共文档会与条目内容悄悄脱钩），而是旧版本转 `archived`（**公共文档保持生效**）+ 新建 `private` 修订并记 `revision_of_note_id`；修订通过审核时用 `supersedesDocumentId` 让旧文档 `inactive`，保证同一标题在库里只有一份生效的「员工经验」。同标题条目处于 `pending` 时再次沉淀返回 409。
- **待审核内容审核期间不可被员工修改**：员工 `PATCH` 待审核/已发布条目返回 409（前端按钮同步禁用只是提示，服务端才是拦截点）；管理员在管理页改待审条目允许，但必须写审计（detail 含 `changedKeys` 与 `previousStatus`）。被驳回的条目可直接修改并重新提交（`rejected→pending` 是 owner 动作）。
- **每日配额是"预占"，不是"先查后调"（本轮加固）**：`reserveDistillQuota` 用 `pg_advisory_xact_lock(2026, userId)` 串行化同一账号的并发请求，在锁内计数并**先写入本次的 `note_distill` 审计行**（审计行即计数器），再放行去调模型——模型调用失败也照样计数，与产品口径一致。`countDistillCallsToday` 只用于展示/对账，单独使用不具备并发安全性。
- **管理端时间筛选与导出必须共用 `parseAdminNoteFilters`**：两处各解析一遍迟早会出现"列表筛了时间、导出没筛"，那是最难被发现的一类不一致。服务端校验 `from ≤ to` 且跨度 ≤ 366 天（超限 400），导出审计记录完整筛选条件与条数。
- **关键词搜索包含结构化字段**：`listNotes` 的 keyword 命中「标题 / 概述 / 原文依据 / `fields::text`」，量级上来后再评估 JSONB 索引或全文检索（当前 `fields::text ILIKE` 够用）。

- **检索相关性下限（关键）**：中文双字切分下「公司」「规定」这类高频词几乎每篇文档都有，只判断"命中数 > 0"会把无关文档捞回来，真实模型会拿它编造制度（违反 A9）。`knowledge.mjs` 因此要求 `命中关键词数 / 关键词总数 ≥ MIN_QUERY_COVERAGE`（默认 **0.2**，可用 `AI_RETRIEVAL_MIN_COVERAGE` 覆盖）。取值来自 `compare-retrieval.mjs` 在夹具语料上的实测：0 → 召回 100% 但负样本 100% 误召；0.2 → 负样本 100% 正确空返回、召回 87%；0.3 以上过度拒绝（空检索率 30%）。**接入真实文档后必须在该语料上重新标定。**
- **同义词兜底召回（2026-10-14）**：员工措辞与文档措辞不一致时（问「考勤 / 上班时间 / 午休」，文档写「作息时间 / 工作时间 / 午餐时间」），原词一个都命中不了，覆盖率门槛必然拦下 —— 实测「考勤」0 条、「员工每天几点上班，中午休息多久？」0 条，而《规章制度》里明确写着作息与出勤条款。`knowledge.mjs` 因此新增 `QUERY_SYNONYMS` + `expandQueryTokens()`：扩展词**只在本轮原词覆盖率不达标且同义词命中 ≥ 2 个**时放行，且**不计入覆盖率的分子分母**。

- **越权拦截文案统一**：「当前账号无权查询该数据，请联系管理员。」禁止提示"你有 A 权限但没有 B 权限"，避免权限探测。
  **但"为什么被拦"必须分层**（2026-09-17 修）：`ai_messages.status = 'blocked'` 有三类来源，
  原先共用这一句，实测把用户引向"我是不是没权限"的错误排查方向 ——
  | 原因 | 含义 | 提示文案（`src/features/ai-agent/blocked-notice.ts`） |
  | --- | --- | --- |
  | `tool_unavailable` | 工具契约已播库、但**当前进程没有实现**（代码合了没重启），与权限无关 | "查询没有执行：所需工具当前不可用（未启用或未实现），与你的账号权限无关，请稍后重试。" |
  | `forbidden` | 确实没权限（账号停用 / 需要管理员） | 「当前账号无权查询该数据，请联系管理员。」 |
  | `wording:*` | 模型自行描述工具范围或直接拒绝，被护栏替换成统一文案，与权限无关 | "本次回答被权限护栏拦下（……与账号权限无关），换个问法再试一次。" |
  **回答正文仍统一**（合规要求，见上）；分层只体现在页面的提示条上。细分原因由编排层写进
  `ai_messages.block_reason`（**迁移 119**）并随 done 事件下发，实时流与历史回看都能分辨。
  新增拒绝码时**必须同时**改 `tools.mjs` 的 `REJECT_REASON`、编排层的文案分支与 `blocked-notice.ts`。
- **上传即生效**：本轮文本/Markdown 上传即生效，无审核流程；补偿控制为「来源与时效强制展示 + 有效期 + 纠错反馈」。
- **PDF / Word / Excel 解析**：本轮不支持，接口明确返回"暂不支持该格式"，不静默失败、不伪装成功（解析库选型对应需求文档 Q6，待确认）。
- **审计不可删**：`ai_audit_logs` / `ai_runs` 无删除接口，也不在 UI 提供删除入口。
- **治理页行内操作图标化后，"可访问名"就是唯一契约（2026-09-15）**：行内操作由文字按钮改成图标后，含义只能由 `aria-label` 承载，而 `verify-ui.mjs`（`getByRole('button', { name: '查看片段' })`）与读屏用户都依赖它。改图标或改文案时同步改 `RowAction` 的 `label` 参数（它同时喂给 Tooltip 与 `aria-label`），**不要只在 Tooltip 上改**——那样界面上写着"设置有效期"、脚本与读屏却仍读到旧名字，属于最难被发现的一类不一致。
- **"折叠"必须留折痕（2026-09-15）**：治理页把低频内容折叠起来时，折叠行右侧要常显当前生效值（技能治理显示"仅手动 · 每日上限 200 · 整理全部字段"、时间筛选显示已选区间），否则"简化"就变成了"藏信息"——管理员得点开才知道当前配置是什么。同理，任何"默认折叠"都要给出**不依赖用户手动操作**的展开条件（提示词审核队列用 `userOpen ?? pendingTotal > 0` 派生：有待审自动展开、无待审才收起），且**不要用 effect 在数据到达后 setState**（多一次级联渲染，还会覆盖用户主动收起的动作）。
- 禁止使用 `console`（ESLint 报错），服务端一律走 `process.stdout.write` 或抛错。
- **销量口径优先级与如实声明**：`analyze_inventory_risk` 的日均销量优先用「产品主数据 → 销售报告」（完整历史，窗口默认 30 天），缺少映射时回退订单快照（近期切片，低置信度）。**两种口径必须在回答里说明**——混用而不说明等于让用户拿不同可靠度的结论做决策。工具输出里的「销量口径」列与摘要句就是为此。
- **统计窗口锚定"数据最后一天"而不是"今天"**：报表是人工导出的滞后数据，用今天做锚点会得到空窗口，把所有 SKU 误判成"无销量"。
- **区分"没卖出去"与"报表没覆盖"**：映射到的 ASIN 在窗口内完全无记录时标记 `hasCoverage=false` 并回退其他口径；只有报表确实覆盖这些日期且销量为 0 时才判滞销。
- **样本不足时不下"积压/滞销"结论**：日均销量来自订单快照（近期切片），实测踩到过"3 天样本 → 判定积压 133 天"。样本不足 7 天时滞销/积压降级为「样本不足」，可售天数仍如实给出并标注样本区间；**断货风险仍按保守告警**（风险不对称：漏报断货的代价远大于误报）。
- **越权时必须阻断"能力枚举"**：实测普通用户请求管理操作时，模型 4 次有 3 次会把自己的可用工具清单念出来（"我这次可用的工具只有…"），等于给越权用户一个权限探测探针。`enforcePermissionWording` 的模式表用**真实样本**固化，容忍"我…具备…能力"这类插入语，并把同义变体统一规整为固定文案——改这里的模式必须拿真实回答验证，不要凭想象写。
- **模型可能间歇性误判权限**：实测 deepseek-chat 有约 1/6 概率拒绝管理员的合法请求。系统提示词规则 7.1/7.2 已明确"判断依据只能是工具列表、工具在列表里就必须调用"，但仍需在验收里保留"管理员不被拦截"这条断言（A5-4），它是这类波动的探测器。
- **分析与数字一律服务端算**（`analytics.mjs`）：ACoS 涨跌、环比/同比、驱动因子分解、异常判定全部在服务端确定性计算，随工具结果一起回灌模型；模型只负责表达。理由：让模型做算术等于允许编造，且 A2 要求"归因主因可复核"。驱动分解采用顺序分解法，两部分**相加恰好等于总变化**（残差为 0），这是可校验的硬性质（有单测锁定）。
- **`today` 与数据覆盖范围必须进提示词**：模型不知道"今天"是哪天，也不知道数据覆盖到哪一天。实测真实模型把"上个月"算成训练数据里的月份，查了空区间后回答"查不到数据"。`renderRuntimeContext` 会把当前日期与各数据集的行数/覆盖区间/导入时间写进系统提示词，并要求超出覆盖范围时明确告知。
- **结构化数据块（`ai_messages.blocks`）**：工具返回 `blocks`（metrics/table/chart），编排层落库、前端用 react-table 与 recharts 渲染。不让模型排版 Markdown 表格——流式输出下会抖动且列易错位、也无法画图。**`chat.mjs` 的 `serializeMessage` 必须返回 `blocks`**，漏了会导致流式结束后表格与图消失（只剩文字）。
- **数据集引用与文档引用分开渲染**：`citation.kind = 'dataset'` 时显示数据集名、覆盖周期、导入时间与"准实时非实时"说明，与文档引用的视觉区分。
- **CSV 导入的编码回退**：中文 Excel 另存 CSV 默认 GBK，`decodeCsvBuffer` 先按 UTF-8 解，出现替换字符再回退 gb18030/gbk/big5。日期解析支持 ISO、斜杠、中文日期与 Excel 序列号。
- **数据时效同时声明"导入时间"与"覆盖至"**：只看导入时间会误导（导入很新但数据其实到上个月），`freshnessSentence` 两者都写。
- **不依赖模型自觉的四条服务端兜底**（真实模型不会稳定遵守格式与措辞要求，实测都踩到了）：
  1. **统一拦截文案**：模型用自己的话描述工具/权限范围、点名无权工具、或自述式拒绝时，`enforcePermissionWording` 一律替换为固定文案；模型若已直接输出固定文案，也会被记为「拦截」写审计（A5 要求拦截并记录）。判定模式在 `prompt.mjs`，可按语料补充。
  2. **声明条**：模型漏写数据来源与截至时间时，`ensureFreshnessDeclaration` 在回答末尾补一条确定性声明（仅在确有引用文档时补，避免"未找到"的回答被加上无效声明）。
  3. **降级返回**：模型没产出总结但检索有结果时，`buildDegradedAnswer` 直接返回检索原文并明示降级状态（需求文档 §9 可用性）。
  4. **知识库强制检索护栏（2026-10-14）**：模型声称"知识库中未找到"、可本轮**一次成功的工具调用都没有**时，`orchestrator.mjs` 用原始提问自己补一次 `search_knowledge`（审计口径与模型主动调用一致：`startRun` → `finishRun`，`toolRuns` 里可见）——命中就 `buildDegradedAnswer` + `KNOWLEDGE_GUARD_NOTICE` 降级返回原文，确实为空才输出 `NO_RESULT_ANSWER`。**为什么必须有**：用户只发来一个词（「作息」「假期」）时，deepseek-chat 会判定"信息不足"跳过检索、直接照抄提示词里的固定文案，而库里该内容 coverage=1.0 可命中 —— 用户看到的是"库里有内容却说找不到"（已复现且线上 `ai_runs` 无记录可证）。护栏的四个前置条件缺一不可：`status==='ok'`、回答命中 `looksLikeNoResultClaim()`、无成功工具调用、且 `search_knowledge` 已注册给该用户（无权限不越权补检索）。**改动此分支前先看 `orchestrator.node-test.mjs` 的 5 个用例**，它们分别钉住"补检索并返回原文""确实为空才答未找到""正常回答不介入""已有成功工具调用不介入""无权限不越权"。
- **新会话的刷新必须用 `conversationIdRef`**：`activeId` 在发起请求时可能还是 `null`，用闭包里的它刷新会刷到 `['ai','messages',0]`，导致回答落库后前端永远拉不回来（表现为"答案闪一下就消失"）。演示模式响应极快会掩盖这个竞态，改动这块逻辑时务必在真实模型下验证。
- **模型密钥存储（需求文档 §8.3 的受控偏离）**：原方案要求密钥只走环境变量、不入库；为支持管理员在后台自助配置，现改为**加密后入库**：
  - 算法 AES-256-GCM（`server/ai-agent/secrets.mjs`），加密密钥取自 `AI_SETTINGS_SECRET`，未配置时回退 `JWT_SECRET`；两者都没有时**拒绝保存**并给出可操作提示，绝不降级成明文存储。
  - 三条不可违反的约束：① 任何接口不回传明文（只回传掩码 `sk-a…b1c2`）；② 审计只记掩码与指纹，不记明文；③ 解密失败按"未配置"处理并向前端标记 `apiKeyInvalid`。
  - **运维注意**：换服务器时要一并带走 `AI_SETTINGS_SECRET`（或 `JWT_SECRET`），否则库里的密文解不开，后台会提示"密钥无法解密"，需重填一次 Key。
  - 配置优先级：**后台配置（数据库）> 环境变量 > 演示模式**。数据库优先是为了让后台改完即时生效、无需重启；环境变量保留给本地开发与 CI。`force_demo` 开关只影响是否使用密钥，不影响已保存的密钥。
- **鉴权不复用 `requireAdmin`**：需求文档要求管理类接口「403 并写审计」，而 `requireAdmin` 直接返回响应、没有插入审计写入的位置。`server/ai-agent/router.mjs` 因此自带 `identityGuard`（每请求回源查 `users`，用库里的 role/status 覆盖 JWT 旧值）+ `adminGuard`（非管理员 403 且写 `forbidden` 审计）。
- **权限判定依赖 `req.user.status`**：`permissions.mjs` 的 `isEnabledUser` 要求 `status === 'enabled'`。`server/index.mjs` 的 `requireUser` 必须把 `status` 一并下发（曾因为漏下发导致所有工具被误判为无权）；AI 路由的 `identityGuard` 是第二道保险。
- **`ai_runs.message_id` 指向本轮的提问消息**：回答消息在流程末尾才创建，工具轨迹挂在提问消息上作为这一轮的锚点；审计台按会话关联两者。
- **左栏宽度偏好（2026-09-14，2026-09-15 收敛为单栏）的三条硬约束**：① **拖拽不能是唯一通道**——WCAG 2.2 要求拖动操作有单指针替代方案，分隔条上的键盘操作（`←/→` 调整、`Home/End` 到极限、**`Enter` 恢复默认**）与双击恢复默认都是必须保留的，别为了"界面干净"把键盘分支删掉；② **存储与显示分离**——`paneWidths` 是用户意图（写 cookie），`displayPaneWidths` 是按容器宽度收敛后的渲染值，窗口变小只收敛**显示**，**不得把收敛结果写回 cookie**（否则用户在大屏设的宽度会被一次小窗口永久改写）；③ **恢复默认必须始终可达**——`onReset` 走 `clearPaneWidths()` + 默认值，栏被拖坏要有一条不用清浏览器 cookie 就能回去的路（当前是双击 / `Enter`）。
- **中栏保底的预算要把分隔条算进去**：`limitPaneWidths` 的可用宽度 = 容器宽 − `MIN_CENTER_WIDTH` − **可见**分隔条（16px × 数量），隐藏的栏既不占宽也不参与预算——漏掉任一项都会表现为"窄屏下莫名拖不动"或"中栏被压到几像素"。
