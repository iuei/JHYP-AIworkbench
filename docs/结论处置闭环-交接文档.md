# 竞品分析结论处置闭环交接摘要

- **最后更新**：2026-09-22
- **范围**：竞品分析的“结论与建议”
- **责任田**：[竞品分析](/Users/lzg/codex/codex项目文件/JHYP-AIworkbench-main/docs/modules/竞品分析.md)

## 目标

让“需处理”结论具备明确处理方式：用户可以查看步骤、复制系统外处理方案、标记已处理，下一次分析再由系统核验是否仍然存在。

## 当前行为

- 待处理：没有处置记录的结论。
- 已销账：用户声明已经处理，暂不代表系统验证通过。
- 已核验：下一次分析中该结论不再命中。
- 重新打开：下一次分析仍命中，记录重新打开次数和核验信息。
- 忽略：用户填写原因后终止自动核验。
- 旧快照没有稳定 `code` 时使用 `legacy:<index>`，可以手动销账，但不参与自动核验。

## 数据与接口

- `competitor_finding_dispositions`：账号级处置台账。
- `competitor_analyses.finding_keys`：分析快照中的可处置结论索引。
- `POST /api/competitor-analyses`：保存分析后执行核验。
- `PUT /api/competitor-analyses/:id/findings/disposition`：标记已处理或忽略。
- `DELETE /api/competitor-analyses/:id/findings/disposition`：撤销处置。
- 任务中心执行竞品分析时也必须执行同一套核验。

## 重要口径

- 处置记录按账号隔离，不提供未审计的管理员跨用户查看。
- 只有当前分析范围包含目标 ASIN 时，才能自动核验对应结论。
- 首页和历史列表显示“当前仍需处理”的状态，不只显示原始快照等级。
- `info` 级信息不计入需处理数量。
- 系统外处理必须给出处理步骤和入口，不能只显示“需立即处理”。

## 当前限制

- 任务中心暂未支持通过 URL 预填分析参数。
- AI 助手历史回答仍采用分析快照口径，不代表当前未销账状态。
- 暂无独立的“我的处置记录”列表页。
