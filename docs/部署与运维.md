# JHYP 智能工作台 —— 部署与运维手册（照着做版）

> 适用：把这个项目放到**阿里云服务器**上长期运行，并知道以后怎么更新代码。
> 你不需要懂 Linux，按本文顺序复制粘贴即可。遇到报错先看最后一节「出问题怎么查」。
>
> 配套文件都在仓库的 `deploy/` 目录里：
> `nginx.conf`（网站入口配置）、`jhyp.service`（后端常驻服务）、`deploy.sh`（一键更新）、`backup.sh`（定时备份）。
>
> **只想在自己 Mac 上长期跑、给同事内网访问？** 0–14 节都不用看，
> 直接看文末「**第 15 节 macOS 本机常驻运行（launchd）**」。

---

## 0. 先想清楚三件事

| 问题 | 结论 |
|---|---|
| 要不要用域名？ | **要域名就必须先 ICP 备案**，否则阿里云会拦截 80/443 端口。没备案就先用 `http://公网IP:8080`（本文有两套配置） |
| 服务器买什么？ | **ECS 或轻量应用服务器，2 核 4G 起**（构建前端比较吃内存，2G 会卡死），系统选 **Alibaba Cloud Linux 3**，系统盘 40G |
| 数据库买什么？ | **RDS PostgreSQL**（你已选定）。购买时选 **PostgreSQL 14 及以上**，因为项目用到 `pgvector` / `pg_trgm` 扩展 |

整体结构（了解即可）：

```
用户浏览器 → 域名/Nginx → 前端页面文件（服务器上的 dist 目录）
                        → /api 开头 → Node 后端(8787) → RDS 数据库
```

## 1. 买云资源（控制台操作）

### 1.1 ECS / 轻量应用服务器
1. 阿里云控制台 → 云服务器 ECS → 创建实例
2. 地域：选离你近的（如华东1-杭州）；**ECS 和 RDS 必须同一个地域**，才能走内网
3. 镜像：Alibaba Cloud Linux 3（或 Ubuntu 22.04）
4. 规格：2 核 4G；系统盘 40G 高效云盘
5. 设置 root 密码（记好）
6. **安全组**：只放行这些端口
   - `22`（SSH 登录，来源建议填你的办公 IP，不要 0.0.0.0/0）
   - `80` 和 `443`（有域名、已备案）
   - 或 `8080`（没备案时的临时入口）
   - ⚠️ **不要放行 5173 / 8787 / 5432**，这些只在本机内部使用

### 1.2 RDS PostgreSQL
1. 控制台 → 云数据库 RDS → 创建实例 → PostgreSQL
2. 版本：**PostgreSQL 14 / 15 / 16**（不要选 13 及以下）
3. 规格：最小规格即可（1 核 2G / 20G 存储起步）
4. 网络类型：**专有网络 VPC**，与 ECS 选同一个 VPC / 交换机（这样走内网，快且不计流量）
5. 创建时设置**高权限账号**（记住账号密码）—— 后面创建扩展必须用它
6. 创建完成后：
   - 在「数据库管理」里新建数据库，例如 `jhyp_workbench`
   - 在「白名单」里加入 **ECS 的内网 IP**（在 ECS 控制台能看到，形如 `172.16.x.x`）
   - 记下 RDS 的**内网地址**（形如 `rm-xxxxxx.pg.rds.aliyuncs.com`）和端口 `5432`

### 1.3 域名（可选）
1. 阿里云 → 域名 → 注册（如 `ai.example.com`）
2. **ICP 备案**：控制台 → 备案 → 提交（需要域名 + 服务器，通常 3–20 个工作日）
3. 备案通过后：域名解析 → 添加 A 记录 → 指向 ECS 的**公网 IP**

> 没备案期间：先用 `http://公网IP:8080`，功能完全一样，只是地址不好看、且是 http。

> ```

> 备份即使失败也不会阻塞上线（`deploy.sh` 会提示但继续），但**首次上线请务必确认备份能跑通**。

## 4. 拿到代码并配置

```bash
# 4.1 建目录
sudo mkdir -p /srv/jhyp
sudo chown -R $USER /srv/jhyp
cd /srv/jhyp

# 4.2 克隆代码（换成你的仓库地址）
git clone <你的仓库地址> app
cd app

# 4.3 生成两份随机密钥（各复制一行输出，第 4.4 步要用）
openssl rand -hex 32     # → 填给 JWT_SECRET
openssl rand -hex 32     # → 填给 AI_SETTINGS_SECRET

# 4.4 建 .env 配置文件
cp .env.example .env
vi .env                  # 按 i 进入编辑，改完按 Esc 再输入 :wq 保存退出
```

`.env` 里**必须**改/填的项（其余保持默认即可）：

```ini
PGHOST=rm-xxxxxx.pg.rds.aliyuncs.com   # RDS 内网地址
PGPORT=5432
PGDATABASE=jhyp_workbench              # 第 1.2 步建的库名
PGUSER=你创建的高权限账号
PGPASSWORD=该账号密码

JWT_SECRET=第 4.3 步生成的第一个随机串
AI_SETTINGS_SECRET=第 4.3 步生成的第二个随机串

INITIAL_ADMIN_LOGIN=admin              # 首次启动会创建这个管理员
INITIAL_ADMIN_PASSWORD=换成强密码

CORS_ORIGIN=https://你的域名            # 没域名就写 http://公网IP:8080
TRUST_PROXY=true                       # 在 Nginx 后面必须开，否则审计记录的 IP 全是 127.0.0.1
TZ=Asia/Shanghai                       # 不设页面时间会差 8 小时
```

> ⚠️ **密码含特殊字符时必须加单引号**：阿里云 RDS 的密码规则强制包含 `!@#$%^&*` 之类的字符，
> 而 `$` 在 Shell 里是变量符号 —— 备份脚本（`deploy.sh` / `backup.sh`）会直接读取这个文件，
> 不加引号会把密码读错。**统一写成这样最安全**：
>
> ```ini
> PGPASSWORD='你的密码原样写在这里'
> ```
>
> 数据库连不上时，先检查这一条。

前端请求地址单独写一个文件（保证前端同源访问后端，不用配跨域）：

```bash
cat > .env.production <<'EOF'
VITE_API_BASE_URL=/api
EOF

chmod +x deploy/deploy.sh deploy/backup.sh 2>/dev/null || true
```

> ⚠️ **`.env` 永远不要提交到 Git**，里面有数据库密码和密钥。

## 5. 初始化数据库

先在 RDS 上开扩展（用高权限账号，在阿里云控制台的「DMS」或本地 `psql` 里执行）：

```sql
-- 连接到 jhyp_workbench 库后执行
CREATE EXTENSION IF NOT EXISTS vector;     -- 向量检索（pgvector）
CREATE EXTENSION IF NOT EXISTS pg_trgm;    -- 中文关键词模糊匹配
-- 验证：
SELECT extname FROM pg_extension WHERE extname IN ('vector','pg_trgm');
```

> 如果提示 `extension "vector" is not available`：到 RDS 控制台的「插件管理 / 扩展管理」里先安装 `vector`，再执行上面的语句；若该实例确实不支持，说明实例内核版本过低，需要升级大版本。

然后在本机（服务器）跑项目自带的初始化：

```bash
cd /srv/jhyp/app
pnpm install --frozen-lockfile
pnpm db:setup          # 建表 + 全部迁移 + 创建第 4.4 步的管理员账号
```

看到「数据库初始化完成。」就成功了。

## 7. 把后端装成后台服务（开机自启、崩了自动重启）

```bash
cd /srv/jhyp/app
sudo cp deploy/jhyp.service /etc/systemd/system/jhyp.service
sudo systemctl daemon-reload
sudo systemctl enable --now jhyp

# 看状态（绿色 active (running) 即正常）
sudo systemctl status jhyp
# 看日志（Ctrl+C 退出）
sudo journalctl -u jhyp -f
```

如果 `User=www-data` 报权限错误，给目录授权：

```bash
sudo chown -R www-data:www-data /srv/jhyp/app
sudo systemctl restart jhyp
```

## 8. 配置 Nginx（对外入口）

```bash
cd /srv/jhyp/app
sudo cp deploy/nginx.conf /etc/nginx/conf.d/jhyp.conf
sudo vi /etc/nginx/conf.d/jhyp.conf     # 改 server_name 成你的域名；没域名就启用文件末尾的 8080 块

# 检查语法并生效
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx
```

打开浏览器访问：

- 有域名且已备案：`https://你的域名`（先完成第 9 步的证书）
- 没备案：`http://公网IP:8080`

看到登录页 → 用第 4.4 步的 `INITIAL_ADMIN_LOGIN / PASSWORD` 登录。

## 9. 上 HTTPS（有域名时）

1. 阿里云控制台 → 数字证书管理服务 → **免费证书** → 申请（每年有免费额度）
2. 域名验证方式选 DNS（按提示加一条解析记录，等几分钟）
3. 签发后点「下载」→ 选 **Nginx** 版 → 得到 `.pem` 与 `.key` 两个文件
4. 上传到服务器：

```bash
sudo mkdir -p /etc/nginx/ssl
# 在你自己的电脑上执行（把两个文件传上去）
scp ai.example.com.pem root@公网IP:/tmp/
scp ai.example.com.key root@公网IP:/tmp/
# 再回到服务器
sudo mv /tmp/ai.example.com.pem /etc/nginx/ssl/
sudo mv /tmp/ai.example.com.key /etc/nginx/ssl/
sudo chmod 600 /etc/nginx/ssl/*
sudo nginx -t && sudo systemctl reload nginx
```

5. 证书**到期前**阿里云会短信提醒，重新申请下载替换即可。

## 11. 以后怎么更新代码（最常用）

### 11.1 你本机：改完代码先自测再提交

```bash
pnpm lint && pnpm build && pnpm test    # 三项都过再提交
git add -A
git commit -m "feat: 这次改了什么"
git push
```

### 11.2 服务器：一条命令更新

```bash
ssh root@你的公网IP
bash /srv/jhyp/deploy.sh
```

这条脚本会自动：**备份数据库 → 拉最新代码 → 装依赖 → 构建前端 → 跑数据库迁移 → 重启后端 → 自检**。

### 11.3 （可选）让 GitHub 自动帮你更新

在仓库 `.github/workflows/ci.yml` 末尾追加下面这段，之后 `git push` 到 main 分支、CI 全绿后就会自动上线：

```yaml
  deploy:
    needs: install-lint-build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - name: 通过 SSH 触发服务器更新
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.ALIYUN_HOST }}          # 服务器公网 IP
          username: ${{ secrets.ALIYUN_USER }}      # 通常是 root
          key: ${{ secrets.ALIYUN_SSH_KEY }}        # 服务器私钥（在 GitHub 仓库 Settings → Secrets 里配置）
          script: bash /srv/jhyp/deploy.sh
```

## 13. 出问题怎么查（先看这里）

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开是 **502 Bad Gateway** | Node 后端没起来 | `sudo systemctl status jhyp` → `sudo journalctl -u jhyp -n 60` |
| 问答**转圈很久才一次性出全文** | Nginx 没关缓冲 | 确认 `nginx.conf` 的 `/api/` 里有 `proxy_buffering off;` 和 `gzip off;`，改完 `sudo nginx -s reload` |
| 登录后马上跳回登录页 | 密钥/跨域配置不对 | `.env` 里 `JWT_SECRET` 非空、`CORS_ORIGIN` 写成实际访问地址，改完重启 `jhyp` |
| 页面时间**差 8 小时** | 没设时区 | `jhyp.service` 里有 `Environment=TZ=Asia/Shanghai`，重装一次并重启 |
| 审计里的 IP 都是 `127.0.0.1` | 没开代理信任 | `.env` 加 `TRUST_PROXY=true`，重启 |
| 上传大文件报 **413** | Nginx 限制体积 | `nginx.conf` 里 `client_max_body_size 64m;`（按需调大）后 reload |
| 数据库连不上 | RDS 白名单没放 ECS 内网 IP | RDS 控制台 → 白名单，加入 ECS 内网 IP |
| `CREATE EXTENSION` 权限不足 | 用的不是高权限账号 | 换成创建 RDS 实例时设置的那个账号 |
| 域名打不开，但 `IP:8080` 正常 | 没备案 / 证书不对 | 先走 8080；备案通过后再切 443 |
| AI 回答提示「演示模式」 | 没配模型密钥 | 登录 →「AI 治理 → 模型与配置」填 API Key（后台优先于环境变量） |
| 页面 404 或刷新后白屏 | SPA 回退没配 | 确认 `nginx.conf` 的 `location / { try_files $uri $uri/ /index.html; }` |
| 部署脚本卡在 `git merge` | 服务器上有手工改动 | 登录服务器 `cd /srv/jhyp/app && git status`，处理后再跑 |

## 14. 千万不要做的事

1. **不要把 `.env` 提交到 Git**（含数据库密码与密钥）。
2. **不要更换 `AI_SETTINGS_SECRET`**：后台已保存的模型/MCP 密钥是加密存储的，换掉就解不开，只能回后台重新填一遍。换服务器时把它一起带走。
3. **不要直接改服务器上的代码文件**：下次 `deploy.sh` 会因为本地有改动而停下来。改代码在你自己电脑上改，然后 push。
4. **不要把 8787 / 5432 端口开在安全组里**（公网直接暴露后端和数据库非常危险）。
5. **不要用 root 长期跑 Node 服务**（`jhyp.service` 里已用普通账号）。
6. **升级前先确认备份成功**：`deploy.sh` 会自动备份，看到「✔ 备份完成」再继续。

## 15. macOS 本机常驻运行（launchd，内网访问用）

> 场景：不买服务器，就在自己的 Mac 上长期跑，同事通过**内网 IP** 访问。
> 配置与脚本都在 `deploy/` 下，**不需要装 pm2，也不需要 nginx**。

### 15.1 一条命令装好

```bash
cd <项目目录>
bash deploy/macos-service.sh install
```

装完会打印内网地址，形如 `http://192.168.1.32:5173`，同事在同一局域网直接打开即可。

| 目的 | 命令 |
|---|---|
| 看状态（服务 + 端口 + 内网地址） | `bash deploy/macos-service.sh status` |
| 重启前后端（**改了后端代码必须执行**） | `bash deploy/macos-service.sh restart` |
| 实时看日志 | `bash deploy/macos-service.sh logs` |
| 立即轮转一次日志 | `bash deploy/macos-service.sh rotate` |
| 卸载（停止服务，日志保留） | `bash deploy/macos-service.sh uninstall` |

### 15.2 三个 launchd 服务是怎么配的

| Label | 作用 | 端口 | 日志 |
|---|---|---|---|
| `com.jhyp.api` | 后端 API（`server/index.mjs`，带 `SERVE_STATIC=false`） | 8787 | `logs/api.log` |
| `com.jhyp.web` | 前端 Vite（用 `.env.development` 的 `/api` + 代理） | 5173 | `logs/web.log` |
| `com.jhyp.logrotate` | 每天 04:00 轮转日志（超 10MB 才切，保留 7 份） | — | `logs/rotate.log` |

要点（改 plist 前务必先读）：

- **为什么拆成两个服务**：`node server/dev.mjs` 会把 API 与 Vite 一起拉起，但子进程挂掉时它自己不退出，
  launchd 的 `KeepAlive` 永远等不到触发条件。拆开后才能各自崩溃、各自自愈。
- **`RunAtLoad` + `KeepAlive`**：登录后自动拉起，进程意外退出自动重启（实测 `kill -9` 后前后端都能自行恢复）。
- **`SERVE_STATIC=false` 不能删**：否则 `index.mjs` 会额外在 5173 起一个静态站，与 Vite 抢端口。
- **开机自启的前提是「用户已登录」**：macOS 的 `LaunchAgents` 在用户登录后才加载，无人登录时不会运行。
  （要做到开机即启，得装成 root 的 `LaunchDaemon`。）
- **脚本里不要写死 `en0`**：本项目实测 IPv4 挂在 `en1` 上（默认路由也走 `en1`），
  `macos-service.sh` 用 `route -n get default` 探测主网卡，换网络也能取到地址。
- 历史的 `launchctl submit` 临时守护（`jhyp-dev-all`，日志在 `/tmp`）会在 `install` 时被自动移除，
  避免它与上述服务抢 8787/5173（不清掉会导致它的 Vite 漂移到 5174 空转）。

### 15.3 为什么内网跑 dev 而不是 dist（重要）

`pnpm build` 的产物把 `VITE_API_BASE_URL` **写死**在 JS 里，而仓库 `.env` 中是 `http://localhost:8787/api`。
内网同事打开这种页面后，请求会打向**他自己的 localhost:8787**，必然失败。

所以本机内网服务固定用 dev 模式：`.env.development` 里 `VITE_API_BASE_URL=/api`，
再由 `vite.config.ts` 的 `server.host: true` + `/api` 代理转发到 8787 —— 浏览器侧同源、无跨域，换 IP 也不用改配置。
**不要**为了"看起来更正式"就改成 `dist` 静态托管，除非同时在网关层做 `/api` 转发。

### 15.4 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 内网打不开、本机正常 | 防火墙拦截或不在同一网段 | 系统设置 → 网络 → 防火墙，允许 node 接受连接 |
| 打印的内网 IP 不对 | 多网卡 | 以 `status` 输出为准；换网络后地址会变 |
| 页面能开，登录报网络错误 | 后端没起来 | `bash deploy/macos-service.sh status` 看 8787 |
| 改了 `server/*.mjs` 不生效 | Node 不做热重载 | `bash deploy/macos-service.sh restart` |
| 前端变卡 / 内存上涨 | Vite dev 长期运行 | `bash deploy/macos-service.sh restart` |
