## 踩过的坑

| 现象 | 根因 | 规避方式 |
| --- | --- | --- |
| `pnpm exec vitest run` 直接失败：缺 Playwright Chromium | 本机未安装自带浏览器，`pnpm exec playwright install chromium` 在本环境下载卡死 | 用系统 Chrome：临时 vitest 配置把 provider 换成 `playwright({ launchOptions: { channel: 'chrome' } })`，配置文件放**工作区根目录**（否则插件与 `@` 别名解析不到），验证完删除 |
| 响应式断点测试永远通过，即使样式没生效 | 测试文件没导入 `@/styles/index.css`，Tailwind 类根本没被应用 | 视口相关断言必须 `import '@/styles/index.css'`（既有 `auth-layout.test.tsx` 就是这么做的） |
| `expect(title.scrollWidth).toBeLessThanOrEqual(title.clientWidth)` 对 `truncate` 元素必然失败 | `truncate` 就是 `white-space: nowrap` + `overflow: hidden`，`scrollWidth > clientWidth` 正是裁剪生效的表现 | 用 `document.documentElement.scrollWidth <= clientWidth` 断言「页面不横向滚动」，这才是真正要防的回归 |
| 长标题把窄屏页面撑出横向滚动 | grid item 默认 `min-width: auto`，`1fr` 列的最小值也是 `auto`，`truncate` 的 nowrap 文本把列撑宽 | 给 grid item 加 `min-w-0`；列表类组件都要检查这一层 |
| 断言「入口顺序」时被页面其他链接干扰 | 「最近活动」的链接也指向 `/competitor-analysis`，按 href 收集会混入 | 用排序按钮的 `aria-label`（`下移 {标题}`）按 DOM 顺序读出入口顺序，不依赖 href |
| `getByText('管理员')` 之类短文案报 strict mode violation | vitest 浏览器模式的 locator 走 Playwright 语义，`exact` 默认 false（子串匹配） | 断言短文案时显式 `{ exact: true }` |
| 测试里 mock 掉 `Main` 后担心布局结论不可信 | 需确认 mock 是否丢掉了关键样式 | `Main` 只有 `px-3 py-4` 与 `@7xl/content:w-full`，不含 overflow 约束，所以横向溢出的结论依然成立；mock 布局组件前先确认它没有承担被测的样式职责 |
