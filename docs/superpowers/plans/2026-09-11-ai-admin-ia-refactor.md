# AI 助手信息架构重构实施计划（使用面 / 治理面分离）

**状态：已交付（2026-09-11）** —— 单测 309 项、`verify-e2e` 43/43（真实模型）、`verify-ui` 59/59、`pnpm run build` 与 `pnpm run lint` 全绿。

**Goal:** 把 AI 助手从"一个模块里混放使用与治理"改成两层：员工面 `/ai-agent`（对话、我的沉淀）＋ 治理面 `/admin/ai/*`（知识库、数据源与导入、经验审核、模型与配置、审计台，仅管理员），并把技能的成本参数从员工手里上收给管理员。

**Spec:** 本次评审结论（`需求文档.md` §5.2/§5.4/§3.3 为业务口径来源）；现状基准见 `docs/modules/AI 助手.md`、`docs/modules/全局布局与导航.md`。

## 背景：评审发现的 3 个结构性问题

1. **数据源与导入页没有任何入口** —— 路由存在、守卫正确，但模块内导航没列它，全仓库无链接指向它。管理员只能手输 URL（AI 数据接入闭环的唯一导入通道不可达）。
2. **系统级配置埋在审计视图里** —— 模型密钥、护栏、工具开关是审计台的第 5 个 tab；审计台的职责是"看历史"，新接手的管理员会在"设置"里找密钥而找不到。
3. **导航把使用面与治理面平铺** —— 管理员视角 5 个同权重入口，再叠审计台自己的 5 个 tab；员工看到 2 个、管理员看到 5 个，同一位置含义随角色变化。且侧边栏是静态数据，普通账号能看到「用户管理」却因服务端 403 只看到报错。

## 已确认的产品口径

| 决策 | 结论 |
| --- | --- |
| 目标信息架构 | 方案 A：治理面 URL 一并迁到 `/admin/ai/*` |
| 技能成本参数 | 上收：管理员设默认值并锁定，员工只能开关 |
| 私有沉淀可见性 | 管理员在**对话检索**中不可见，仅管理页可见（沿用上一轮结论） |
| 依赖 | 不新增依赖 |

## 踩过的坑

| 现象 | 根因 | 规避方式 |
| --- | --- | --- |
| 登录后不跳转、UI 冒烟首项即失败 | `.env` 的 `CORS_ORIGIN` 只含 5173/5174，启动时用 shell 变量覆盖成 5175 无效（`.env` 仍生效），浏览器拦掉登录请求 | 验证实例用 `.env` 中已允许的端口（现为 5173/5174），或直接用标准开发服务 8787+5173 |
| 问答页 SSE 返回 200 后被 abort、答案不渲染 | 新增/删除路由文件期间 Vite 开发服务器漂移（依赖预构建与路由树不同步） | 改完路由重启 dev server，必要时 `rm -rf node_modules/.vite` |
| 控制台报 `Invalid hook call` / `Cannot read properties of null (reading 'useMemo')` | 同上：依赖预构建重建期间页面同时加载新旧 dep URL，出现两个 React 实例 | 清 `.vite` 缓存并重启，预热一次页面后再跑冒烟 |
| 员工侧页面白屏 | 前端已更新（读 `state.policy`）而服务端仍是旧版本，字段缺失即在 `.fieldKeys` 抛错 | 组件内兜底 `state.policy ?? 由 config 派生`；**新增必返字段要同时考虑旧服务端的读法** |
