# 市场洞察基础版开发方案

## 目标

在不一次性实现全部市场情报能力的前提下，建立一个可持续扩展的“市场洞察”模块。第一阶段重点解决两个问题：

1. 现有市场调研结果只在页面临时展示，不能保存、回看和复用。
2. 竞品分析、类目调研和新品候选之间缺少一条清晰的业务连接。

完成后，用户可以从一个统一入口查看类目概览、产品地图和产品分析，并把有价值的结果带入新品项目。

## 范围

### 纳入第一阶段

- 新增“市场洞察”功能边界和页面骨架。
- 产品地图的基础列表和筛选：站点、节点、时间和关键词。
- 类目概览：市场规模、价格结构、集中度、新品结构和重点产品。
- 保存和回看市场透析报告。
- 复用竞品分析，补充父体/子体变体趋势和明细导出。
- 将产品或报告关联到产品开发候选池。
- 统一展示来源、抓取时间、缓存命中情况和数据缺失状态。

### 暂不纳入第一阶段

- 品牌和店铺的完整分析模型。
- 类目级关键词、SERP 和广告获客经济。
- 自动定时抓取、消息通知和复杂监控规则。
- 正式利润核算、成本核算和合规结论。
- 跨站点、跨币种市场汇总。
- 重新设计全部侧边栏和仪表盘。

## 推荐页面结构

```text
市场洞察
├── 产品地图
├── 类目洞察
├── 产品与竞品
└── 机会记录
```

侧边栏只新增“市场洞察”一个入口；内部使用顶部同级导航。现有产品开发和竞品分析入口保留，避免旧链接失效。

## 开发顺序

### 阶段 0：确认数据和边界

- 盘点现有市场调研返回字段和竞品分析返回字段。
- 确认报告快照需要保存的字段：站点、节点、筛选条件、结果、来源、抓取时间、创建人。
- 确认产品地图第一版只使用已有公开数据，不新增未经验证的指标。
- 在实现前检查迁移版本号，不能复用已应用的版本号。

### 阶段 1：报告快照能力

- 新增市场报告快照表和迁移。
- 新增报告列表、保存和详情接口。
- 市场调研页增加“保存报告”和“打开历史报告”。
- 历史报告读取冻结结果，不重新请求第三方数据。
- 增加来源、抓取时间和估算标识。

### 阶段 2：市场洞察页面骨架

- 新增市场洞察路由和模块布局。
- 新增产品地图基础表格。
- 新增类目洞察概览区。
- 把已有市场调研结果接入新页面。
- 复用现有表格、筛选、分页和空态规范。

### 阶段 3：竞品与新品关联

- 在产品与竞品页面复用现有 ASIN 分析。
- 增加父体/子体变体明细和导出。
- 增加“加入新品项目”入口。
- 关联报告、ASIN 和候选产品，但不改变现有候选数据的所有者隔离。

### 阶段 4：验证与文档同步

- 运行受影响模块测试、`pnpm run lint` 和 `pnpm run build`。
- 验证旧的 `/product-dev/market`、竞品分析和对比历史链接仍可用。
- 验证报告保存后刷新仍可回看，且不会触发重复抓取。
- 更新 `docs/modules/市场洞察.md`、`产品开发.md` 和 `竞品分析.md` 的影响范围与历史变更。

## 数据设计建议

第一阶段建议新增一张不可变报告表，先避免过早拆分过多表：

```text
market_insight_reports
  id
  owner_user_id
  marketplace
  scope_type       -- category / node / asin
  scope_key
  scope_label
  filters_json
  result_json
  source_meta_json
  fetched_at
  created_at
```

后续有定时监控需求时，再增加产品快照、监控规则和变化事件表。不要在第一阶段为了未来监控一次性加入复杂调度模型。

## 验收标准

- 用户可以从市场洞察入口进入产品地图和类目洞察。
- 市场调研结果可以保存，并在离开页面后重新打开。
- 历史报告展示保存时的结果，不因当前数据变化而改变。
- 产品地图明确显示站点、来源、抓取时间和估算字段。
- 产品分析可以查看父体下的子体趋势，并导出明细。
- 产品或报告可以关联到新品项目。
- 未登录用户不能访问报告数据；用户只能看到自己有权限的数据。
- 旧产品开发市场调研和竞品分析路径不回归。
- `pnpm run lint`、`pnpm run build` 和受影响测试通过。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| 第三方接口字段或额度变化 | 保存来源与调用元数据，接口异常时保留可读错误，不写入伪造数据 |
| 市场估算被误认为真实经营数据 | UI 明确显示“第三方估算”和抓取时间 |
| 报告结果过大 | 列表只返回摘要，详情页再读取完整快照 |
| 旧页面和新页面重复建设 | 新页面复用领域层和缓存，不复制采集逻辑 |
| 新入口导致侧边栏变深 | 只新增一个一级入口，内部使用顶部同级导航 |

## 当前结论

第一阶段的重点不是把所有市场分析都做完，而是先建立稳定的数据资产：可保存的报告、统一的数据口径、可回看的产品地图，以及通往新品项目的关联入口。品牌、店铺、广告和自动监控在基础数据稳定后再逐步增加。

## 当前进度（2026-09-22）

- 阶段 1 已完成：报告快照迁移、账号隔离 API、市场调研页保存与历史回看。
- 阶段 2 已启动：新增 `/market-insights` 工作台，包含“类目洞察 / 报告记录”两个真实页面；类目洞察复用现有市场调研结果，报告记录读取冻结快照。
- 产品地图暂不伪造数据，待已有公开数据层提供稳定的产品字段和来源口径后再接入表格。
