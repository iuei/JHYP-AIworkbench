# M-B 分析能力增强实施计划（从被动问答到主动发现）

> **状态：已交付（2026-09-11）**。验收：单测 214/214、`verify-e2e --live` 21/21、`verify-ui` 38/38、数据类问题 12/12。

**Goal:** 让 Agent 从"用户问什么答什么"变成"主动指出哪里出了问题"——运营每天真正要问的不是"某个 ASIN 怎么样"，而是"**哪些** ASIN 需要我处理"。

**Spec:** `需求文档.md` §4 场景二/场景三、§5.1 回答卡片结构；M-A 计划 `docs/superpowers/plans/2026-09-11-data-channel-mvp.md`

## 交付内容

| 能力 | 说明 |
| --- | --- |
| `scan_amazon_anomalies` | 扫描某站点周期内**全部 ASIN**，按严重度排序输出异常清单与命中信号 |
| `analyze_inventory_risk` | 按 SKU 算样本日均销量与可售天数，判定断货/积压/滞销，给出建议补货量 |
| `query_amazon_performance` 支持不传 ASIN | 全站聚合 + 各 ASIN 排行（"哪个 ASIN 最差"） |
| 柱状图渲染 | 回答卡片的 chart 块支持 bar（ASIN 对比、ACoS 排行） |
| 严重度模型 | ACoS 超线 +2、转化率超线 +2、三类趋势信号各 +1；0=正常、1-3=需关注、≥4=高风险 |

## 关键设计决策

### 决策 1：异常判定与归因全部服务端算
`scanAsinAnomalies` 的 severity 是权重累加，`judgeAnomalies` 用 PRD 给的阈值；模型只负责表达。
理由同 M-A：让模型做判断等于允许它编造，而且"哪些 ASIN 有问题"必须可复核、可复现。

### 决策 2：样本不足时不下"积压/滞销"结论
日均销量来自订单快照（近期切片）。**实测踩到过**：3 天样本就判出"积压 133 天"，这种结论会让运营去清库存，风险不对称。
现在的处理：样本不足 7 天时，滞销/积压一律降级为「样本不足」，可售天数仍如实给出但标注样本区间；**断货风险仍按保守告警**（宁可误报不漏报）。

### 决策 3：越权回答必须阻断"能力枚举"
实测发现：普通用户请求管理操作时，模型 4 次里有 3 次会**把自己的可用工具清单念出来**
（"我这次可用的工具只有知识库检索、Amazon 广告/销售表现查询……"）。这等于给越权用户一个权限探测探针，违反 PRD §5.1。
现在 `enforcePermissionWording` 用真实样本固化的模式识别这类自述，统一替换为固定文案并记 `tool_blocked` 审计。

### 决策 4：工具选择重叠时不强求唯一
"哪个 ASIN 的 ACoS 最高"用 `query_amazon_performance`（全站排行）或 `scan_amazon_anomalies` 都合理，验收允许两者任一。

## 本轮修复的缺陷

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 模型把"上个月"推成去年同月（查了 2025-08） | 提示词只给了"以今天为基准"的规则，没给算好的例子 | `renderRuntimeContext` 直接给出"上个月 = 2026-08-01 ~ 2026-08-31"的示例，并点明"不是去年同月" |
| 模型间歇性误拒管理员的合法请求（1/6） | 提示词规则 7.1 的举例恰好是"重建索引"，反而让模型把这类请求与"无权"关联 | 规则改为"判断依据只能是本次提供的工具列表"，并新增 7.2：工具在列表里就必须调用，严禁自行预判权限 |
| 越权时模型念出可用工具清单（3/4） | 泄露检测词表漏了"这次""只具备…能力"等真实写法 | 用实测样本固化模式，容忍插入语；同义变体统一规整为固定文案 |
| 快照类数据集"覆盖"导入退化成合并 | 无周期列的数据集走覆盖模式时不删除任何行 | 快照类（库存/订单）覆盖 = 整表替换；日报类仍按周期替换 |
| 验收脚本把"模型答对"误判为失败 | 数字匹配只生成 `6427.95`，模型写的是 `6,427.95`（千分位） | 匹配器补齐千分位与多种小数位写法 |
